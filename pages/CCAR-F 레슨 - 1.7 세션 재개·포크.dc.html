조사나 리팩터링이 며칠에 걸치면 "어제 대화로 돌아갈지, 거기서 갈라질지, 새로 시작할지"를 정해야 한다. 세션은 메시지·도구 호출·도구 결과를 담은 대화 기록이라, 되살리면 에이전트는 그때 읽은 파일 내용을 다시 근거로 삼는다. 그래서 재개 여부는 "저장된 도구 결과를 지금도 믿을 수 있는가"로 정한다. 코드가 그대로면 재개로 탐색 비용을 아끼고, 코드가 크게 바뀌었으면 요약을 들고 새 세션을 여는 편이 안전하다.

습득 포인트
  • Claude Code CLI에서 세션 찾기: --continue, --resume(선택기·이름·ID), 이름 붙이기(-n, /rename)
  • Agent SDK의 continue · resume · fork_session 차이와 세션 ID 포착
  • 포크가 복사하는 것(대화)과 복사하지 않는 것(파일 시스템 등)
  • 재개 후 바뀐 파일만 알려 표적 재분석하기 vs 구조화 요약으로 새 세션 시작하기
01

세션에 무엇이 남는가

A session is the conversation, not the disk

Claude Code는 대화를 프로젝트 디렉터리별로 로컬에 계속 저장한다. 기본 위치는 ~/.claude/projects/<project>/<session-id>.jsonl이고, 줄마다 메시지·도구 호출·결과 같은 항목이 들어 있다. 이 형식은 내부용이라 버전마다 바뀌므로, 스크립트에서 세션 데이터가 필요하면 /export나 claude -p --output-format json을 쓰라는 것이 문서 권고다.

항목재개할 때
대화 기록 (메시지·도구 호출·결과)복원된다. 압축(compaction)된 세션은 마지막 요약 + 요약되지 않은 메시지 + 그 이후 메시지로 열린다
실행 중 끊긴 도구 호출다시 실행하지 않는다
모델, --agent로 시작한 에이전트대체로 그대로 이어진다 (에이전트의 도구 제한 포함)
권한 모드재개 경로에 따라 다르다. 터미널에서 --continue나 이름·ID로 재개하면 복원되고, 선택기·-p 경로는 대체로 새 세션 기준을 따른다
--mcp-config, --settings, --add-dir 등 실행 플래그복원되지 않는다. 다시 넘겨야 한다 (settings.json은 실행할 때 다시 읽힌다)
파일 시스템세션에 들어 있지 않다. 그사이 바뀐 파일은 기록에 반영되지 않는다
핵심 한 줄

Agent SDK 문서의 표현대로 세션은 대화를 저장할 뿐 파일 시스템을 저장하지 않는다. 에이전트가 고친 파일을 스냅숏으로 남기고 되돌리려면 file checkpointing을 따로 쓴다.

02

CLI: 이어 가기와 이름으로 돌아가기

--continue · --resume · names
claude -n index-lag # 시작할 때 이름 붙이기 /rename index-lag # 세션 안에서 이름 붙이기·바꾸기 claude --continue # 현재 디렉터리의 가장 최근 세션 claude --resume # 세션 선택기 열기 claude --resume index-lag # 이름으로 바로 재개 claude --resume <session-id> # ID로 재개 (다른 프로젝트까지 찾아본다)
명령동작주의
--continue현재 디렉터리의 가장 최근 세션claude -p·Agent SDK·/loop로 시작한 세션은 건너뛴다 (claude -p --continue는 포함)
--resume <이름>정확히 일치하는 세션을 바로 재개같은 이름이 여럿이면 그 이름으로 검색된 선택기가 열린다. 세션 안의 /resume <이름>은 이때 오류를 낸다
--resume <ID>현재 프로젝트와 worktree → 이 기계의 다른 프로젝트 순으로 탐색일치하는 사본이 여러 곳이면 임의로 고르지 않고 not-found로 처리
--from-pr <번호>그 PR에 연결된 세션만 선택기에 표시Claude가 PR을 만들면 자동으로 연결된다

이름을 붙이지 않은 세션에도 레이블이 두 개 생긴다. 디렉터리 이름에 두 글자 접미사를 붙인 기본 표시 이름(예: my-app-3f)은 재개 핸들로 쓸 수 없고, 첫 프롬프트를 요약해 만든 생성 제목은 쓸 수 있다. 여러 작업을 병렬로 돌린다면 직접 이름을 붙이는 것이 가장 확실하다.

시험 가이드 표현 vs 현재 문서

시험 가이드는 --resume <session-name>으로 이름 붙은 세션을 이어 간다고 쓴다. 현재 CLI도 그렇게 동작하며, 이름은 -n/--name, /rename, 선택기의 Ctrl+R 등으로 붙인다. 반면 Agent SDK의 resume 옵션은 세션 ID(UUID)만 받는다. SDK에서 rename_session()으로 제목을 붙일 수는 있지만, 재개하려면 결과 메시지의 session_id를 저장해 두거나 list_sessions()로 ID를 찾아야 한다.

04

포크: 같은 출발점에서 두 갈래로

Forking from a shared baseline

한 번 해 둔 코드베이스 분석을 바탕으로 두 접근을 비교하고 싶을 때 포크한다. 포크는 원본 기록을 복사한 새 세션(새 ID)을 만들고 원본은 그대로 둔다. 예: 성능 분석 세션을 마친 뒤, 한 갈래에서는 캐시 계층 추가를, 다른 갈래에서는 N+1 쿼리 제거를 설계하게 해 결과를 비교한다.

Claude Code CLI
/branch try-cache-layer # 복사본으로 전환, 원본은 /resume으로 복귀 claude --resume perf-audit --fork-session # 셸에서 이름 붙은 세션을 포크
Agent SDK (Python)
ClaudeAgentOptions(resume=baseline_id, fork_session=True) # 결과의 session_id = 포크의 새 ID fork_session(baseline_id, up_to_message_id=msg_uuid, title="N+1 제거안") # 특정 메시지까지만 복사해 갈라지기
항목포크 후
대화 기록포크 시점까지 복사. 이후 두 기록은 독립
파일 시스템공유된다. 포크한 에이전트가 파일을 고치면 같은 디렉터리의 다른 세션에도 실제로 보인다
"이 세션 동안 허용" 권한/branch는 같은 프로세스라 유지, --fork-session으로 새 프로세스를 띄우면 다시 승인
파일 체크포인트 (SDK fork_session())포함되지 않는다. 포크 이전 체크포인트로는 되감을 수 없다
두 갈래가 실제로 코드를 고친다면

갈래마다 별도 git worktree(claude --worktree <이름>)에서 작업해 파일 충돌을 막는다. Claude Code의 /fork는 대화를 새 백그라운드 세션으로 복사하며, 그 복사본은 코드를 고치기 전에 자기 worktree를 만들도록 지시받는다. 반대로 포크 없이 같은 세션을 두 터미널에서 재개하면 두 쪽 메시지가 한 트랜스크립트에 섞인다.

05

재개할까, 새로 시작할까

Stale tool results and fresh starts

재개한 세션 속 도구 결과는 그것을 읽은 시점의 스냅숏이다. 그사이 동료가 파일을 바꿨다면 에이전트는 낡은 Read 결과를 근거로 추론할 수 있다. Claude Code의 Edit 도구는 마지막 읽기 이후 디스크에서 바뀐 파일을 알아채고 필요하면 다시 읽지만, 이는 편집 순간의 안전장치일 뿐 앞서 내린 분석 결론까지 갱신해 주지는 않는다.

BAD · 변경을 알리지 않는 재개
어제 하던 거 이어서 해 줘.

무엇이 바뀌었는지 모르는 에이전트는 낡은 결과를 사실로 쓰거나, 안전하려고 전부 다시 탐색한다.

GOOD · 바뀐 범위를 짚는 재개
어제 이후 바뀐 파일: - src/report/export_csv.py (열 순서 변경) - src/report/filters.py (날짜 필터를 UTC 기준으로 변경) 이 두 파일만 다시 읽고, 어제 결론 중 영향받는 항목을 갱신해 줘.

변경 범위가 좁으면 재개 + 변경 통지로 표적 재분석한다.

변경이 넓거나(대형 리팩터링 병합), 대화가 실패한 시도로 가득하면 새 세션을 열고 필요한 것만 구조화 요약으로 넘긴다.

문서 근거

Prompting best practices는 컨텍스트 창이 비워질 때 압축 대신 새 창에서 시작하는 방법도 고려하라고 한다. 최신 모델은 로컬 파일 시스템에서 상태를 잘 찾아내므로 "progress.txt, tests.json, git 로그를 검토하라"처럼 시작 방법을 구체적으로 지시한다. Claude Code best practices도 같은 문제를 두 번 고쳤는데도 틀리면 세 번째 수정 대신 /clear 후 배운 점을 담은 새 프롬프트를 쓰라고 권한다.

시험 판단 기준
  • 이전 도구 결과가 대부분 유효하고 바뀐 파일이 몇 개 → 재개 + 바뀐 파일과 변경 내용 명시
  • 대규모 변경으로 탐색 결과 대부분이 낡음 → 새 세션 + 구조화 요약
  • 같은 출발점에서 두 방향 비교 → 포크 (+ 코드를 고치면 worktree)
  • 무관한 새 작업 → /clear (이전 세션은 저장되어 /resume으로 돌아갈 수 있다). 기록은 두되 줄이려면 /compact <초점>

시험 함정 · 흔한 오해

오해claude --continue는 마지막으로 쓴 세션을 어디서든 연다.
사실현재 디렉터리의 가장 최근 세션을 연다. -p·Agent SDK로 만든 세션은 건너뛴다. 특정 세션이 필요하면 이름이나 ID로 --resume한다.
오해포크하면 파일 변경도 갈래별로 분리된다.
사실포크는 대화 기록만 갈라진다. 파일 격리는 git worktree, 되돌리기는 file checkpointing으로 따로 해결한다.
오해Agent SDK에서도 세션 이름을 resume에 넘기면 된다.
사실SDK의 resume은 세션 ID를 받는다. 이름으로 재개하는 것은 CLI의 --resume <이름>이다.
오해세션을 재개하면 그동안 바뀐 파일이 자동으로 반영된다.
사실기록 속 도구 결과는 읽은 시점 그대로다. 바뀐 파일을 알려 다시 읽게 하거나, 변경이 크면 요약을 들고 새로 시작한다.
오해재개하면 처음 실행할 때 준 플래그도 모두 되살아난다.
사실--mcp-config, --settings, --plugin-dir, --add-dir 등은 복원되지 않아 다시 넘겨야 한다.
