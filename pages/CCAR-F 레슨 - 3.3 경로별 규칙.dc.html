경로 한정 규칙: .claude/rules/와 paths

.claude/rules/ · paths frontmatter · glob 패턴 · 지연 로드 · 하위 CLAUDE.md와 비교 · 로드 확인

참고 레슨 · CertSafari 3.3  |  출제 도메인: 도메인 3 · Claude Code Configuration & Workflows (20%)

3.1 CLAUDE.md3.2 명령·스킬3.3 경로별 규칙3.4 플랜 모드3.5 반복 개선3.6 CI/CD

Terraform 작성 규칙이나 테스트 파일 규칙처럼 일부 파일에만 해당하는 지침을 매 세션 싣는 것은 컨텍스트 낭비다. .claude/rules/의 규칙 파일에 paths frontmatter를 달면, Claude가 일치하는 파일을 다룰 때만 그 규칙이 들어온다. 시험은 glob 패턴 해석과 "하위 CLAUDE.md로 할지, 경로 규칙으로 할지"를 묻는다. 디렉터리를 가로질러 흩어진 파일 유형에 대한 규칙은 glob으로 범위를 정한 규칙 파일 하나에 둔다.

습득 포인트
  • .claude/rules/*.md의 YAML frontmatter paths에 glob 패턴을 적어 조건부로 활성화하기
  • 경로 규칙은 일치하는 파일을 다룰 때만 로드되어 무관한 컨텍스트와 토큰을 줄인다
  • **/*.test.tsx처럼 위치와 상관없이 파일 유형으로 규칙을 적용하기
  • 코드베이스 곳곳에 흩어진 파일에는 하위 디렉터리 CLAUDE.md보다 경로 규칙이 유리한 이유
  • 규칙이 실제로 로드됐는지 확인하고, 로드되지 않는 흔한 원인 짚기

시험 가이드 표현 vs 현재 문서

가이드는 경로 규칙이 "일치하는 파일을 편집할 때" 로드된다고 적는다. 현재 문서는 편집만이 아니라 Read로 읽을 때도(Write·Edit, 그리고 읽기로 인정되는 단일 파일 Bash 조회 포함) 로드된다고 설명한다. 문서가 트리거로 드는 것은 이 파일 단위 동작이며, 검색 결과에 파일 이름이 나온 것만으로 로드된다고 설명하지는 않는다.

경로 규칙은 메시지 이력에 들어가므로 압축(compaction) 때 나머지 대화와 함께 요약되어 사라지고, 일치 파일을 다시 다룰 때 다시 로드된다. 압축 뒤에도 반드시 남아야 하는 규칙이라면 paths를 빼거나 루트 CLAUDE.md로 옮긴다.

02

paths frontmatter 쓰기

The only field a rule reads
# .claude/rules/terraform.md --- paths: - "infra/**/*.tf" - "infra/**/*.tfvars" --- - provider 버전은 versions.tf에서만 고정한다 - 모듈 입력 변수에는 type과 description을 모두 적는다 - 변경 전 terraform plan 결과를 요약해 보여 준다 # .claude/rules/tests.md — 쉼표로 구분한 문자열도 된다 --- paths: "**/*.test.ts, **/*.spec.ts" --- - 외부 HTTP는 msw 핸들러로 막는다. 실제 네트워크 호출 금지
  • 규칙 파일에서 Claude Code가 읽는 frontmatter 필드는 paths 하나다. 다른 필드는 오류 없이 무시되고, frontmatter는 로드 전에 제거된다.
  • 값은 YAML 목록이나 쉼표로 구분한 문자열로 쓴다.
  • 패턴의 기준 디렉터리: 프로젝트 규칙은 그 규칙의 .claude 폴더를 담은 디렉터리, ~/.claude/rules/의 개인 규칙은 세션의 기본 작업 디렉터리다.
함정 · YAML이 깨지면 항상 로드된다

frontmatter의 YAML이 파싱되지 않으면 Claude Code는 frontmatter를 무시하고 paths가 없는 규칙처럼 로드한다. 즉 조건부 규칙이 조용히 매 세션 규칙이 된다. claude --debug로 파싱 오류를 확인한다.

03

glob 패턴 읽기

*, **, braces, brackets
패턴일치일치하지 않음 (예)
**/*.test.tsx어느 깊이든 모든 .test.tsxButton.tsx, Button.test.ts
infra/**/*infra/ 아래 모든 파일tools/infra.sh
*.md프로젝트 루트의 마크다운docs/guide.md
apps/admin/pages/*.tsx그 디렉터리 바로 아래의 .tsxapps/admin/pages/users/list.tsx
src/**/*.{ts,tsx}src/ 아래 .ts와 .tsx (중괄호 확장)src/style.css
assets/\[old]/**이름에 대괄호가 든 assets/[old]/ 아래 (이스케이프)—
  • 중괄호 그룹은 패턴 수를 곱으로 늘린다({a,b}/*.{ts,tsx} → 4개). 규칙 하나의 paths 전체가 확장 패턴 1,000개·4MiB 예산을 공유하며, 예산을 넘는 패턴은 확장되지 않은 채 쓰여 아무 파일과도 맞지 않는다.
  • [는 [abc] 같은 대괄호 표현의 시작이다. 대괄호 표현으로 읽을 수 없는 [가 든 패턴은 무효가 되어 아무것도 맞지 않고, 같은 규칙의 다른 패턴은 계속 동작한다. 문자 그대로의 [는 \[로 쓴다.
04

경로 규칙 vs 하위 디렉터리 CLAUDE.md

Scattered files vs owned directories
방식파일 위치로드 시점어울리는 경우
하위 디렉터리 CLAUDE.md그 디렉터리 안, 코드 옆그 디렉터리에서 시작할 때, 또는 그 안의 파일을 다룰 때디렉터리 담당자가 자기 규칙을 코드와 함께 관리
.claude/rules/ 경로 규칙루트의 중앙 .claude/paths glob과 일치하는 파일을 다룰 때규칙을 한곳에 모으고 싶거나, 같은 규칙이 흩어진 여러 경로에 적용될 때

시나리오: 스토리북 작성 규칙이 apps/admin, apps/shop, packages/ui 등 열두 곳의 *.stories.tsx에 똑같이 적용된다.

BAD · 디렉터리마다 복사
apps/admin/CLAUDE.md # 스토리 규칙 사본 apps/shop/CLAUDE.md # 사본 packages/ui/CLAUDE.md # 사본 …×12

한 곳을 고치면 나머지가 어긋난다. 그 디렉터리의 다른 파일을 다룰 때도 스토리 규칙이 딸려 온다.

GOOD · 파일 유형으로 한 번
# .claude/rules/storybook.md --- paths: - "**/*.stories.tsx" --- - args는 타입이 있는 Meta로 선언한다

위치와 무관하게 스토리 파일을 다룰 때만 로드된다.

선택 기준
  • 기준이 파일 유형·이름 규칙이고 여러 디렉터리에 흩어져 있다 → 경로 규칙
  • 기준이 한 패키지·서비스의 스택이고 그 팀이 관리한다 → 하위 CLAUDE.md
  • 매번 직접 호출하는 절차나 가끔 필요한 참고 자료 → 스킬(스킬에도 paths 필드가 있어 일치 파일 작업 시 자동 활성화를 제한할 수 있다)
05

로드됐는지 확인하고, 안 될 때 따지기

Verify and troubleshoot

경로 규칙은 세션 중간에 로드되므로 시작 직후 /context의 Memory files 목록에는 보이지 않는다. 로드 시점을 보려면 InstructionsLoaded hook을 쓴다. 이 이벤트는 지침 파일이 로드될 때마다 발생하며 입력에 load_reason(path_glob_match 등), globs, trigger_file_path가 담긴다. 차단 기능은 없는 관찰용이다.

// .claude/settings.local.json — 경로 규칙 로드만 기록 { "hooks": { "InstructionsLoaded": [ { "matcher": "path_glob_match", "hooks": [ { "type": "command", "command": "jq -c '{file_path, globs, trigger_file_path}' >> ~/rules-load.log" } ] } ] } }
규칙이 기대대로 로드되지 않을 때
증상확인할 것
조건부여야 할 규칙이 매 세션 들어온다frontmatter YAML 파싱 실패 → paths 없는 규칙으로 취급
심볼릭 링크로 가져온 공유 규칙 중 일부만 로드된다작업 디렉터리 밖을 가리키는 링크는 외부 가져오기 승인 후에도 paths 없는 규칙만 로드된다
형제 git worktree의 파일에는 적용되지 않는다그 worktree에서 시작하거나 /cd로 세션을 옮긴다
긴 규칙의 뒷부분을 따르지 않는다지연 로드 파일의 파일별 크기 한도(200K 컨텍스트에서 40,000자)를 넘으면 앞부분만 들어간다 → 나눈다
--setting-sources에서 project를 뺐다프로젝트 규칙은 건너뛴다

시험 함정 · 흔한 오해

오해.claude/rules/로 옮기기만 하면 해당 파일을 다룰 때만 로드된다.
사실paths가 없으면 매 세션 시작 시 로드된다. 조건부 로드는 paths를 지정해야 일어난다.
오해*.md는 저장소 전체의 마크다운 파일과 일치한다.
사실프로젝트 루트의 마크다운만이다. 모든 깊이를 포함하려면 **/*.md를 쓴다.
오해경로 규칙은 한 번 로드되면 압축 뒤에도 계속 남는다.
사실메시지 이력의 일부라 압축 때 요약되고, 일치 파일을 다시 다룰 때 재로드된다.
오해규칙 frontmatter에 description이나 priority를 넣으면 로드 순서를 조정할 수 있다.
사실규칙이 읽는 필드는 paths뿐이고, 나머지는 경고 없이 무시된다.
