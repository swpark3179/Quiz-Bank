  • 한 응답에서 여러 Agent 호출을 내 서브에이전트를 병렬로 생성하기
  • 절차 대신 목표와 품질 기준을 주는 위임 프롬프트
  • 공통 분석 기준점에서 갈라져 대안을 탐색하는 포크(fork)
01

Agent 도구로 생성하기

Spawning through the Agent tool

프로그램 방식에서는 query() 옵션의 agents에 서브에이전트 정의를 넣는다. 그러면 메인 에이전트(코디네이터)의 Claude가 Agent 도구를 호출해 그중 하나를 띄운다. 계약서 검토 시스템으로 예를 들면 다음과 같다.

options = ClaudeAgentOptions( allowed_tools=["Read", "Grep", "Glob", "Agent"], # Agent = 서브에이전트 생성 도구(구 Task) agents={ "clause-finder": AgentDefinition( description="계약서에서 해지·위약금·책임 제한 조항을 찾아 원문과 위치를 보고할 때 사용", prompt="너는 계약 조항 탐색 담당이다. 조항마다 원문, 파일명, 조항 번호, 쪽을 그대로 적고 해석은 하지 않는다.", tools=["Read", "Grep", "Glob"], # 읽기 전용 model="haiku", ), "risk-reviewer": AgentDefinition( description="이미 찾아 둔 조항을 근거로 법적 위험도를 평가할 때 사용", prompt="너는 계약 위험 검토자다. 주어진 조항 원문만 근거로 판단하고, 근거 조항의 id를 반드시 인용한다.", tools=["Read"], ), }, )

Claude가 내는 Agent 도구 호출의 입력에는 prompt(서브에이전트에게 건네는 위임 메시지)와 subagent_type(agents에 정의한 이름, 생략하면 내장 general-purpose)이 들어가고, run_in_background·model·isolation 같은 선택 필드도 있다. 실행 중 메시지 스트림에서 서브에이전트 생성은 name이 "Agent"인 tool_use 블록으로 보이고, 서브에이전트 안에서 나온 메시지에는 parent_tool_use_id가 붙는다.

시험 가이드 표현 vs 현재 문서

가이드는 'Task 도구'와 "코디네이터의 allowedTools에 Task가 있어야 한다"고 쓴다. 현재 문서에서 이 도구는 Agent다(Claude Code v2.1.63에서 이름 변경, Task는 별칭으로 계속 인식되고 system:init의 도구 목록에는 아직 Task로 표시). 또 현재 SDK의 allowedTools는 '사용 가능 목록'이 아니라 '자동 승인 목록'이며, Agent 도구는 원래 승인 없이 실행되는 도구로 분류된다. 서브에이전트 생성을 막으려면 disallowedTools에 Agent를 넣고, 에이전트 정의의 tools 목록을 직접 지정했다면 거기에 Agent가 있어야 그 에이전트가 생성할 수 있다. 시험에서는 "코디네이터 설정에 Task(Agent)를 포함한다"를 정답으로 고른다.

AgentDefinition 필드

Configure each subagent type
필드정하는 것메모
description (필수)언제 이 서브에이전트를 쓸지. Claude가 작업과 맞춰 보는 기준짧고 구체적으로. 상세 지침은 prompt로 보낸다
prompt (필수)서브에이전트의 시스템 프롬프트 — 역할, 규칙, 출력 형식그 서브에이전트가 실행될 때만 컨텍스트에 들어간다
tools허용 도구 목록생략하면 서브에이전트가 쓸 수 있는 도구를 모두 상속. 목록에 없는 도구는 그 세션에 아예 없다
disallowedTools상속 도구에서 뺄 목록tools와 함께 쓰면 disallowedTools가 우선
model모델 별칭·ID, 'inherit'는 메인과 동일단순 탐색은 작은 모델로 비용을 줄인다
maxTurns서브에이전트의 턴 상한도달하면 결과가 '부분 결과'로 표시되고 재개할 수 있다
background·effort·skills·mcpServers·memory실행 방식, 추론 강도, 미리 불러올 스킬, MCP 서버, 지속 메모리필요할 때만 지정

Claude는 description을 보고 자동으로 위임 대상을 고른다. 특정 서브에이전트를 확실히 쓰게 하려면 프롬프트에서 이름을 댄다("clause-finder 에이전트로 해지 조항을 찾아라"). 위임이 일어나지 않는다면 먼저 description이 '언제 쓰는지'를 분명히 말하는지 확인한다.

03

맥락은 프롬프트로만 건너간다

Pass complete findings, keep attribution

서브에이전트는 부모 대화를 보지 못하고, 같은 서브에이전트라도 호출할 때마다 새 인스턴스로 시작해 이전 호출을 기억하지 않는다. "앞에서 찾은 조항으로 위험도를 평가해 줘"라고만 쓰면 risk-reviewer는 '앞에서'가 무엇인지 모른다. 앞 단계 결과는 위임 프롬프트에 직접, 그리고 판단에 필요한 원문 그대로 넣는다.

BAD · 참조만 던짐
prompt: "clause-finder가 찾은 조항을 바탕으로 위험도를 평가하라"

서브에이전트에게는 그 결과가 없다. 추측하거나 파일을 처음부터 다시 뒤진다.

GOOD · 내용과 출처를 분리해 전달
목표: 아래 조항의 위험도를 상·중·하로 평가 <findings> [{"id": "F1", "text": "갑은 30일 전 서면 통지로 …", "source": {"file": "supply_2026.pdf", "clause": "12.3", "page": 7}}, …] </findings> 평가마다 근거 id(F1 …)를 인용할 것

본문(text)과 출처(source)가 분리돼 있어 종합 단계를 거쳐도 어느 문서 몇 쪽인지가 남는다.

핵심은 내용과 메타데이터의 분리다. 출처를 문장 속에 섞어 쓰면("공급계약서 7쪽에 따르면…") 요약·재작성 과정에서 쉽게 떨어져 나간다. id로 참조하게 하면 최종 결과의 주장마다 출처를 역추적할 수 있다.

무엇을 넣지 말까

필요 없는 대화 전체를 붙여 넣으면 컨텍스트 격리의 이점이 사라진다. 기준은 '이 과제를 처음 받는 유능한 동료가 알아야 할 것'이다. 같은 서브에이전트의 작업을 이어 가야 한다면 새로 띄우지 말고, Agent 도구 결과에 담긴 agentId로 재개(resume)한다.

04

병렬 생성은 한 응답에서

Fan out in a single response

병렬 도구 사용과 같은 원리다. Claude는 한 응답에 tool_use 블록을 여러 개 낼 수 있고 Agent 호출도 마찬가지다. 코디네이터가 한 응답에서 Agent를 세 번 부르면 세 서브에이전트가 함께 시작해, 전체 시간이 합이 아니라 가장 느린 하나의 시간에 가까워진다. 턴마다 하나씩 부르면 앞 결과를 기다리는 직렬 실행이 되기 쉽다.

턴마다 1개
턴1: Agent(공급계약) → 보고 턴2: Agent(용역계약) → 보고 턴3: Agent(임대차계약) → 보고
한 응답에 3개
턴1: Agent(공급계약) Agent(용역계약) Agent(임대차계약) → 동시에 진행

병렬을 끌어내려면 코디네이터 프롬프트에 "서로 독립적인 조사는 한 번에 동시에 위임하라"고 적는다. 반대로 조항 탐색 → 위험 평가처럼 앞 결과가 뒤 프롬프트의 재료인 단계는 병렬로 낼 수 없다.

현재 문서의 실행 방식

현재 Claude Code와 Agent SDK에서는 서브에이전트가 기본적으로 백그라운드로 실행된다. Agent 도구 결과가 먼저 status: "async_launched"로 돌아오고 보고는 이후 턴에 도착하며, 다음 행동에 보고가 필요하면 Claude가 기다린다. 동시 실행은 기본 20개까지다. 그래도 독립 과제를 한 응답에 함께 내는 것이 병렬화의 기본형이고, 시험은 이것을 정답으로 본다.

05

절차가 아니라 목표와 기준을 준다

Goals and quality criteria over procedures
BAD · 절차형
1. "충전 요금 2026"으로 검색 2. 상위 3개 결과를 연다 3. 각 페이지에서 첫 번째 표를 찾는다 4. 표의 첫 행을 복사한다

검색 결과가 예상과 다르면 막히거나, 맞지 않는 표를 그대로 가져온다.

GOOD · 목표형
목표: 2026년 국내 급속 충전 요금 체계 파악 범위: 공공 사업자 + 민간 상위 3사, 회원가 출력: 사업자별 kWh당 요금 표 + 출처 URL·기준일 품질: 공식 공지·정부 자료 우선, 기준일이 다른 수치는 섞지 말고 따로 표시

어떻게 찾을지는 서브에이전트가 상황을 보며 정한다.

Anthropic은 서브에이전트마다 목표, 출력 형식, 쓸 도구와 출처에 대한 안내, 명확한 과제 경계를 주라고 하고, 프롬프트에는 엄격한 규칙보다 좋은 휴리스틱을 담는 편이 낫다고 정리한다. 서브에이전트가 상황에 맞춰 방법을 바꿀 여지를 남겨야 개방형 과제에서 적응할 수 있다.

06

포크: 같은 출발점에서 갈라지기

Fork from a shared baseline

한 번 분석해 둔 상태에서 서로 다른 두 접근을 비교하고 싶을 때, 접근마다 분석을 처음부터 반복하는 것은 낭비다. 포크는 지금까지의 대화를 복사한 새 갈래를 만들어 같은 기준점에서 각자 다른 방향으로 진행하게 한다.

세션 포크 (Agent SDK)포크 서브에이전트 (Claude Code)일반 서브에이전트
만드는 법resume에 원래 session ID + fork_session=True (TS: forkSession: true)Agent 도구의 subagent_type: "fork", 또는 /subtaskAgent 도구 + 정의 이름
시작 맥락원래 세션 이력의 복사본부모 대화 전체위임 프롬프트뿐
원본과의 관계새 session ID. 원래 세션은 그대로라 둘 다 따로 재개 가능최종 결과만 부모로 돌아옴최종 결과만 부모로 돌아옴
쓰임같은 분석에서 대안 A/B를 각각 이어 가기배경 설명이 너무 많아 일반 서브에이전트로는 비효율일 때범위가 분명한 독립 과제
포크가 갈라 주지 않는 것

포크는 대화 이력만 갈라진다. 포크한 쪽이 파일을 고치면 같은 디렉터리의 다른 세션에도 그대로 보인다. 파일 변경까지 되돌리려면 file checkpointing을, 작업 공간을 분리하려면 worktree(isolation: "worktree")를 쓴다.

시험 함정 · 흔한 오해

오해서브에이전트는 부모의 시스템 프롬프트와 대화를 물려받는다.
사실포크가 아니면 자기 시스템 프롬프트, 위임 프롬프트, CLAUDE.md, 도구 정의만 갖고 시작한다.
오해앞 단계 결과는 짧게 요약해 넘길수록 효율적이다.
사실판단에 필요한 원문과 출처 메타데이터가 사라지면 근거 없는 종합이 나온다. 완전한 결과를 구조화해 넘긴다.
오해병렬로 돌리려면 턴마다 Agent를 하나씩 부르면 된다.
사실독립 과제는 한 응답에서 여러 Agent 호출로 함께 낸다.
오해포크하면 작업 파일도 함께 갈라진다.
사실대화 이력만 갈라진다. 파일은 checkpointing이나 worktree로 따로 관리한다.
