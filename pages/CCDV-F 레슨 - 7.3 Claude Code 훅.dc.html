Claude Code 훅: 이벤트·매처·PreToolUse 결정

훅(hook)은 Claude Code 수명 주기의 정해진 시점에 실행되는 사용자 정의 핸들러다. 모델이 무엇을 의도하든 코드가 매번 같은 방식으로 돌기 때문에, 프롬프트로는 보장할 수 없는 정책을 집행하는 데 쓴다. 시험의 핵심은 세 가지다. 어느 이벤트가 행동을 실제로 막을 수 있는가, 매처와 if가 무엇을 기준으로 거르는가, 그리고 종료 코드와 JSON 결정이 각각 어떤 결과를 내는가. "exit 0이면 승인", "exit 1이면 차단", "PostToolUse로 되돌린다", "훅의 allow가 deny 규칙을 이긴다"는 모두 단골 오답이다.

습득 포인트
  • 주요 훅 이벤트가 언제 실행되는지, 그중 어떤 이벤트가 행동을 막을 수 있는지 구분한다
  • 매처 값이 정확한 이름 목록으로 평가되는지 정규식으로 평가되는지 판단하고, if로 인자까지 거른다
  • 핸들러 다섯 유형과 설정 위치별 적용 범위를 알고, 팀 전체에 걸 가드레일의 위치를 고른다
  • PreToolUse 입력에서 검사할 필드(tool_input.command 등)를 찾는다
  • 종료 코드 0·2·기타와 stdout JSON의 조합이 만드는 결과를 예측하고, permissionDecision 값을 쓴다
  • 훅 결정과 권한 규칙의 우선순위, Agent SDK 콜백의 같은 패턴을 설명한다
01

훅은 모든 도구 호출에서 도는 결정적 계층

Hook events and when they fire

훅 이벤트는 세션·턴·도구 호출 단위로 나뉜다. 가드레일 관점에서 중요한 것은 도구 루프의 이벤트들이다.

묶음이벤트실행 시점
세션SessionStart, SessionEnd세션 시작·재개, 세션 종료
턴UserPromptSubmit, Stop프롬프트가 제출되어 Claude가 처리하기 전 / Claude가 응답을 마쳤을 때
도구 루프PreToolUse, PermissionRequest, PostToolUse, PostToolUseFailure도구 호출 실행 전 / 권한 결정이 필요할 때 / 호출 성공 후 / 호출 실패 후
설정·기타ConfigChange, Notification, SubagentStop, PreCompact 등세션 중 설정 파일 변경 / 알림 전송 / 서브에이전트 종료 / 압축 전
'모든 도구 호출'의 예외

PreToolUse와 PostToolUse는 에이전트 루프의 모든 도구 호출에서 실행되지만, EndConversation 호출만은 둘 다 건너뛴다. "*" 매처로 모든 도구를 기록하는 감사 훅도 이 호출은 기록하지 못한다. EndConversation은 지속적인 악성 입력에 대한 최후 수단 등으로 세션을 끝내는 도구로, 파일이나 데이터를 읽거나 바꾸지 않으며 권한 프롬프트도 없고, 다른 도구가 남아 있는 한 deny 규칙으로도 막을 수 없다.

02

어떤 이벤트가 행동을 멈출 수 있나

Exit code 2 behavior per event

행동을 막으려면 그 행동이 일어나기 전에 실행되는 이벤트여야 한다. 행동 뒤에 실행되는 이벤트는 관찰하거나 보고할 수만 있다. 종료 코드 2의 의미가 이벤트마다 다른 이유다.

이벤트막을 수 있나exit 2를 내면
PreToolUse예도구 호출을 막는다. stderr가 거부 사유로 Claude에 간다
UserPromptSubmit예프롬프트를 막아 Claude에 닿지 않게 한다
Stop예Claude가 멈추지 못하게 해 대화를 이어 가게 한다(실행 차단이 아니다)
ConfigChange예설정 변경이 적용되지 않게 한다. 단 policy_settings는 예외
PermissionRequest아니요exit 2가 존중되지 않는다. 거부하려면 JSON의 decision 객체를 쓴다
PostToolUse아니요stderr를 Claude에 보여 줄 뿐이다. 도구는 이미 실행되었다
Notification아니요종료 코드와 stderr가 무시된다
시험 판단 축
  • "파괴적 명령이 절대 실행되지 않게"는 PreToolUse뿐이다. PostToolUse는 너무 늦고, Stop은 턴이 끝날 때 돌며, Notification은 막지 못한다
  • PostToolUse에서 decision: "block"이나 updatedToolOutput을 써도 Claude가 보는 것만 바뀐다. 쓴 파일, 실행된 명령, 보낸 요청은 이미 효과를 냈다
  • PostToolUse exit 2는 '경고를 Claude에 전달'하는 용도로는 유효하다. exit 0의 stderr는 Claude가 보지 못하기 때문이다
03

매처와 if 조건으로 겨냥하기

Matchers filter tool names, if filters arguments

matcher는 도구 이벤트에서 도구 이름만 본다. 값에 어떤 문자가 들어 있느냐에 따라 평가 방식이 갈린다.

매처 값평가 방식예
"*", "", 생략모두 일치모든 도구
영문자·숫자·_·-·공백·,·|만정확한 이름, 또는 정확한 이름 목록Bash는 Bash만. Edit|Write와 Edit, Write는 그 두 도구만
그 밖의 문자가 하나라도 있음JavaScript 정규식(앵커 없음)^Notebook은 Notebook으로 시작하는 도구, mcp__memory__.*는 memory 서버의 모든 도구

정규식은 부분 일치라서 Edit.*는 Edit과 NotebookEdit을 모두 잡는다. 전체 일치가 필요하면 ^Edit$처럼 감싼다. 반대로 mcp__memory(뒤에 .* 없음)는 정확한 문자열로 평가되어 어떤 도구와도 일치하지 않는다.

도구 인자까지 거르려면 핸들러에 if를 둔다. if는 권한 규칙 문법으로 도구 이름과 인자를 함께 맞춰 보며, 규칙은 하나만 쓴다(&&·||·목록 없음). PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied에서만 동작하고, 다른 이벤트에 if를 단 훅은 실행되지 않는다. 문서는 if를 최선 노력(best-effort) 필터로 보고, 확실한 허용·거부는 권한 시스템에 맡기라고 한다.

① EVENT
이벤트 발생 (예: PreToolUse)
→
② MATCHER
도구 이름이 매처와 맞는지
→
③ IF
인자가 if 규칙과 맞는지
→
④ HANDLER
핸들러 실행 (일치한 훅은 병렬)
→
⑤ RESULT
Claude Code가 종료 코드·JSON에 따라 진행·차단

핸들러 유형과 설정 위치

Handler types and where hook configuration lives
command · http · mcp_tool
셸 명령(입력은 stdin), 이벤트 JSON을 URL로 POST, 구성된 MCP 서버의 도구 호출. 결정적 규칙 집행에 쓴다.

Claude 모델에 프롬프트를 보내 한 번의 판단을 받는다. 규칙보다 판단이 필요한 조건에 쓴다.

위치범위버전 관리로 공유되나

.claude/settings.json한 프로젝트예. 저장소에 커밋하면 클론하는 모두에게 적용

저장소를 클론하는 모든 개발자에게 같은 가드레일을 걸려면 커밋된 프로젝트 .claude/settings.json에 둔다. 조직 전체에 우회할 수 없게 강제하려면 관리형 설정이다. 사용자 설정과 로컬 설정은 각자의 컴퓨터에만 있으므로, 팀원 한 명이 거기에 훅을 넣어도 다른 사람의 클론에는 적용되지 않는다.

05

PreToolUse가 받는 입력

What a PreToolUse hook receives

command 훅은 stdin으로 JSON을 받는다. 공통 필드(session_id, cwd, permission_mode, hook_event_name 등)에 더해 PreToolUse는 tool_name, tool_input, tool_use_id를 받는다. 가드레일이 검사해야 할 것은 인자다. tool_name은 "Bash"라는 사실만 알려 줄 뿐이고, 실제 명령 문자열은 tool_input.command에 있다. Edit·Write라면 tool_input.file_path를 본다.

{ "hook_event_name": "PreToolUse", "permission_mode": "default", "tool_name": "Bash", "tool_input": { "command": "terraform destroy -auto-approve", "description": "Tear down staging stack" }, "tool_use_id": "toolu_01Qm..." }
06

종료 코드로 막기

Exit 0, exit 2, and everything else
#!/bin/bash # .claude/hooks/block-destructive.sh INPUT=$(cat) CMD=$(echo "$INPUT" | jq -r '.tool_input.command // empty') if echo "$CMD" | grep -Eq 'terraform +destroy|DROP +DATABASE'; then echo "차단: 이 저장소에서는 '$CMD'를 실행할 수 없습니다" >&2 exit 2 # 차단. stderr가 거부 사유로 Claude에 간다 fi exit 0 # 이의 없음. 승인이 아니다
{ "hooks": { "PreToolUse": [{ "matcher": "Bash", "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/block-destructive.sh" }] }] } }
stdout \ 종료 코드exit 0exit 2그 밖의 코드 (예: 1)
스키마를 통과한 JSON 객체성공. 필드가 적용된다차단. 필드는 읽지만 차단을 뒤집지 못한다(allow도 통과 못 함)성공 취급. 종료 코드는 무시되고 필드만으로 결정
파싱 실패·스키마 위반 JSON비차단 오류차단. stderr가 사유비차단 오류
일반 텍스트 또는 출력 없음성공 (결정 없음)차단. stderr가 사유비차단 오류. 행동은 진행된다
exit 0 ≠ 승인

PreToolUse 훅이 아무것도 출력하지 않고 exit 0으로 끝나면 '결정 없음'이다. 호출은 일반 권한 흐름으로 넘어가고, 규칙과 모드에 따라 사용자에게 확인을 물을 수 있다. 훅은 거부할 수는 있지만, 조용히 있는다고 승인하지는 않는다.

exit 1 ≠ 차단

Unix 관례와 달리 유효한 JSON 없는 exit 1은 비차단 오류다. 행동은 그대로 진행되고 transcript에 hook error 알림만 남는다. 정책을 집행하려면 exit 2를 쓰거나, exit 0 + JSON 결정을 쓴다.

훅이 시작하지 못하거나(경로 오류), 시간 초과되거나, 잘못된 JSON을 내면 대부분의 이벤트에서 행동이 그대로 진행된다. PreToolUse의 command·http·mcp_tool 훅도 시간 초과 시 호출을 막지 않고 일반 권한 흐름으로 넘긴다. 정책 훅이 실패할 때 막히게 하려면 command·http 훅에 "onFailure": "block"을 설정한다(Claude Code v2.1.295 이상).

07

구조화된 결정: deny · ask · allow · defer

PreToolUse decision control

PreToolUse는 다른 이벤트처럼 최상위 decision이 아니라 hookSpecificOutput 안에 결정을 담는다. JSON으로 결정을 돌려줄 때는 exit 0으로 끝내는 것이 의도된 방식이다.

{ "hookSpecificOutput": { "hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "운영 DB 스키마 변경은 마이그레이션 PR로만 허용" } }
값효과사유(permissionDecisionReason)는
"deny"도구 호출을 막는다Claude에게 보인다
"ask"사용자에게 확인을 받는다권한 프롬프트에서 사용자에게 보인다
"allow"권한 프롬프트를 건너뛴다디버그 로그에만 남는다
"defer"턴을 끝내 나중에 재개하게 한다(-p 비대화형 모드 필요)디버그 로그에만 남는다
allow는 규칙을 뚫지 못한다

훅이 "allow"를 돌려줘도 deny와 ask 규칙은 훅 결과와 무관하게 평가된다. 일치하는 deny 규칙은 호출을 막고, 일치하는 ask 규칙은 여전히 확인을 받는다. 관리형 설정의 deny도 마찬가지다. 반대로 exit 2로 막는 훅은 권한 규칙 평가 전에 호출을 멈추므로, allow 규칙이 있어도 차단이 적용된다. 여러 PreToolUse 훅이 서로 다른 결정을 내면 deny > defer > ask > allow 순으로 이긴다. updatedInput으로 인자를 바꾸면 권한 규칙은 바뀐 입력을 기준으로 평가된다.

08

Agent SDK에서 같은 가드레일

Callback hooks in the Agent SDK

Agent SDK의 훅은 종료 코드 대신 콜백 함수가 돌려주는 객체로 결정한다. 출력 형식은 셸 훅의 JSON과 같고, 빈 객체 {}는 '변경 없음·결정 없음'이다. 매처 규칙도 설정 파일과 같다.

from claude_agent_sdk import ClaudeAgentOptions, HookMatcher async def block_destructive(input_data, tool_use_id, context): cmd = input_data["tool_input"].get("command", "") if "terraform destroy" in cmd: return {"hookSpecificOutput": { "hookEventName": input_data["hook_event_name"], "permissionDecision": "deny", "permissionDecisionReason": "terraform destroy 금지"}} return {} # 결정 없음 → 일반 권한 흐름 options = ClaudeAgentOptions(hooks={ "PreToolUse": [HookMatcher(matcher="Bash", hooks=[block_destructive])]})
항목SDK 콜백의 동작
평가 순서훅이 가장 먼저 실행된다. 훅의 deny는 bypassPermissions 모드에서도 적용된다
allow의 한계훅이 allow를 돌려줘도 deny·ask 규칙은 그대로 평가된다
PreToolUse 시간 초과Claude Code가 콜백을 취소하고 도구 호출을 막는다(셸 command 훅의 기본 동작과 다르다)
여러 훅병렬 실행. 권한 결정은 가장 제한적인 결과가 적용된다

시험 함정 · 흔한 오해

오해PostToolUse 훅이 exit 2를 내면 방금 실행된 명령의 효과가 취소된다.
사실도구는 이미 실행되었다. exit 2는 stderr를 Claude에 보여 줄 뿐이고, 되돌리는 기능은 없다.
오해PreToolUse 훅이 출력 없이 exit 0으로 끝나면 호출이 승인된다.
사실결정이 없을 뿐이다. 일반 권한 흐름이 그대로 진행되어 확인 프롬프트가 뜰 수 있다.
오해정책 위반을 찾으면 exit 1로 끝내면 된다.
사실유효한 JSON 없는 exit 1은 비차단 오류라 행동이 진행된다. 막으려면 exit 2나 deny JSON을 쓴다.
오해훅이 permissionDecision: "allow"를 돌려주면 deny 규칙에 걸린 호출도 실행된다.
사실deny·ask 규칙은 훅 결과와 무관하게 평가된다. allow는 프롬프트를 건너뛸 뿐이다.
오해Edit|Write 매처는 정규식이라 이름에 Edit이 들어간 도구를 모두 잡는다.
사실영문자와 |로만 된 값은 정확한 이름 목록이다. 정확히 Edit과 Write만 잡는다.
오해PermissionRequest 훅도 exit 2로 권한 요청을 거부할 수 있다.
