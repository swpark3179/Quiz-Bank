MCP(Model Context Protocol)는 이슈 트래커·DB·모니터링 같은 바깥 시스템을 도구와 리소스로 Claude에 연결하는 표준 프로토콜이다. 이 서브도메인은 서버를 "어디에 등록하느냐"와 "등록한 뒤 에이전트가 실제로 잘 쓰게 만드느냐"를 함께 묻는다. 설정 파일의 위치가 공유 범위를 정하고, 도구 설명과 리소스가 에이전트의 선택을 정한다.

습득 포인트
  • local · project · user 세 스코프의 저장 위치(~/.claude.json / .mcp.json)와 공유 범위 구분
  • .mcp.json에 ${VAR} · ${VAR:-default}를 써서 비밀값을 커밋하지 않고 팀과 설정 공유
  • 연결된 모든 서버의 도구가 함께 후보가 되는 구조와, 현재 기본값인 tool search(지연 로딩)
  • MCP 도구 설명을 구체적으로 써서 Grep 같은 내장 도구보다 알맞게 선택되게 하기
  • 표준 연동은 기존 커뮤니티 서버, 팀 고유 업무는 자체 서버 — 그리고 목록·스키마는 MCP 리소스로 노출
01

스코프: 이 서버를 누가 받는가

local · project · user

claude mcp add는 --scope 값에 따라 서버 정의를 다른 파일에 쓴다. 파일 위치가 곧 "이 저장소를 클론한 모든 사람이 받는가, 나만 받는가"를 결정한다.

스코프저장 위치로드 범위어울리는 서버 (예)
local (기본값)~/.claude.json의 현재 프로젝트 항목 아래나 · 이 프로젝트만이 저장소에서만 시험해 보는 벡터 DB 서버
project저장소 루트의 .mcp.json (커밋)클론한 모든 사람결제팀 전원이 쓰는 오류 추적 서버
user~/.claude.json의 최상위 mcpServers나 · 모든 프로젝트어느 저장소에서나 쓰는 개인 메모 서버
# 팀 공유: .mcp.json 생성·갱신 claude mcp add --transport http errtrack --scope project https://errtrack.example.com/mcp # 개인·전 프로젝트 claude mcp add --transport http notes --scope user https://notes.example.com/mcp # --scope 생략 = local (이 프로젝트, 나만) claude mcp add --transport http vecdb-trial https://vecdb.example.com/mcp
시험 가이드 표현 vs 현재 문서

시험 가이드는 "project(.mcp.json) vs user(~/.claude.json)" 두 갈래로 설명한다. 현재 문서는 기본값인 local 스코프를 포함한 세 가지이며, local과 user는 같은 ~/.claude.json에 저장되고 "현재 프로젝트 항목 아래냐, 최상위냐"로만 갈린다. 조직 관리자가 managed 설정으로 서버를 배포하는 경로도 별도로 있다.

같은 이름이 여러 곳에 있을 때

Claude Code는 같은 서버를 한 번만 연결하고, 우선순위가 가장 높은 출처의 항목 전체를 쓴다. 스코프 사이에 필드를 병합하지 않는다. 우선순위는 local → project → user → 플러그인 제공 서버 → claude.ai 커넥터 순이다. 세 스코프끼리는 이름으로, 플러그인·커넥터는 엔드포인트(URL·명령)로 중복을 판단한다. 엔드포인트가 다른 동명 서버는 claude mcp list와 /mcp에 경고가 뜬다.

스코프 판단 축
  • 팀원 모두에게 필요하고 저장소와 함께 버전 관리할 설정인가 → project
  • 나만 쓰지만 모든 저장소에서 필요한가 → user
  • 이 저장소에서 잠깐 시험하거나 남에게 보이면 안 되는가 → local
  • project 서버는 대화형 세션에서 승인 프롬프트를 거친다. claude -p·Agent SDK는 묻지 않고 로드하므로 막을 서버는 disabledMcpjsonServers로 제외한다.
02

비밀값 없이 .mcp.json 공유하기

Environment variable expansion

.mcp.json은 커밋되는 파일이므로 토큰을 그대로 적으면 저장소 이력에 남는다. 대신 서버 항목의 command, args, env, url, headers 값에서 환경 변수를 참조한다. 형식은 ${VAR}와 기본값을 주는 ${VAR:-default} 두 가지다.

BAD · 토큰이 커밋된다
{"mcpServers": { "deskhub": { "type": "http", "url": "https://deskhub.internal.example/mcp", "headers": { "Authorization": "Bearer dh_live_8f2c..."}}}}

클론한 모든 사람과 이력에 실제 토큰이 노출된다.

GOOD · 각자 환경 변수로 주입
{"mcpServers": { "deskhub": { "type": "http", "url": "${DESKHUB_URL:-https://deskhub.internal.example}/mcp", "headers": { "Authorization": "Bearer ${DESKHUB_TOKEN}"}}}}

파일은 공유하고, 값은 팀원 각자의 셸 환경에서 채운다.

확장 규칙에서 자주 나오는 경우
상황동작
변수가 없고 기본값도 없음설정은 로드된다. claude mcp list와 /mcp에 누락 경고가 뜨고, ${VAR} 문자열이 확장되지 않은 채 쓰인다
변수를 빈 문자열로 설정"설정된 것"으로 본다 → :-default가 적용되지 않고 빈 값으로 확장된다
원격 서버 url·headers에서 자격 증명류 변수 참조ANTHROPIC_API_KEY 같은 Claude Code 자체 자격 증명, 클라우드 제공자 자격 증명, NPM_TOKEN 같은 알려진 자격 증명은 빈 값으로 읽힌다 → 보통 401로 연결 실패
/mcp, claude mcp list/get 출력참조를 이름(${VAR})으로 보여 주며 확장된 값을 노출하지 않는다
실무 메모

빈 값으로 읽히는 이름은 문서에 예시로만 나오므로 DESKHUB_TOKEN처럼 팀 고유 이름이 안전하다. url이 있는 항목에는 "type": "http"를 꼭 적는다. 없으면 stdio로 읽혀 건너뛴다.

03

모든 서버의 도구가 함께 후보가 된다

Discovery · naming · tool search

세션이 시작되면 Claude Code는 설정된 서버 전부에 연결을 시작하고, 각 서버에 tools/list를 보내 도구의 name · description · inputSchema를 받는다. local·project·user 스코프, 플러그인, claude.ai 커넥터에서 온 도구가 한 세션 안에서 동시에 후보가 되며, 서버를 추가했다고 해서 그 서버 도구가 우선되지는 않는다.

  • 호출 이름은 mcp__<서버이름>__<도구이름>이다(예: mcp__deskhub__search_tickets). 권한 규칙, Agent SDK의 allowedTools, 스킬의 allowed-tools, hook matcher에 이 이름을 그대로 쓴다.
  • 서버가 list_changed 알림을 보내면 대화형 세션은 목록을 다시 받아 오므로 재연결이 필요 없다. -p와 Agent SDK에서는 도구 목록만 새로 고친다.
  • Agent SDK는 mcpServers 옵션이나 .mcp.json(project 설정 소스 사용 시)으로 서버를 붙인다. 도구가 호출되지 않으면 allowedTools에 "mcp__deskhub__*" 승인이 있는지부터 본다.
시험 가이드 표현 vs 현재 문서

가이드는 "모든 서버의 도구가 연결 시점에 발견되어 동시에 사용 가능하다"고 적는다. 후보가 된다는 점은 지금도 같다. 다만 현재 Claude Code는 tool search가 기본값이라 세션 시작 시 도구 이름과 서버 instructions만 컨텍스트에 들어가고, 전체 스키마는 Claude가 ToolSearch로 필요한 도구를 찾을 때 로드된다. ENABLE_TOOL_SEARCH=false로 끄면 모두 미리 로드되고, auto는 도구 정의가 컨텍스트의 10% 이상일 때만 지연 로딩을 켠다.

그래서 서버를 만드는 쪽은 검색될 단어를 설명 앞부분에 둬야 한다. 미리 로드되는 도구 설명·서버 instructions는 4,096자, tool search로 로드되는 설명은 16,384자에서 잘리며, 검색 매칭은 짧은 쪽 한도 안의 텍스트만 본다.

04

MCP 도구가 내장 도구에 밀리지 않게

Descriptions that earn the call

Claude Code에는 이미 Grep·Bash 같은 내장 검색 수단이 있다. MCP 도구 설명이 "코드 검색" 한 줄뿐이면 모델은 익숙한 내장 도구로 로컬 파일을 뒤진다. 공식 도구 정의 가이드는 설명이 도구 성능에 가장 중요한 요소라고 보고, 무엇을 하는지 · 언제 쓰고 언제 쓰지 말지 · 각 파라미터의 의미 · 무엇을 반환하지 않는지를 최소 3~4문장으로 쓰라고 권한다.

BAD · 내장 Grep과 구분이 안 된다
{"name": "xref", "description": "Index lookup."}

무엇을 주는지, 로컬에 없는 저장소까지 본다는 점이 드러나지 않는다.

GOOD · 범위 · 반환값 · 사용 시점
{"name": "xref_callers", "description": "Queries the company-wide symbol index (42 service repos, including ones not cloned locally) and returns every call site of a function as repo, path, line and commit SHA. Use it when a change may affect other services. For text inside the current checkout, the built-in search is faster. Does not return file contents; read the hits separately."}

기존 서버를 쓸까, 직접 만들까

상황선택이유
GitHub, Jira, Sentry, Notion 같은 표준 서비스 연동기존 서버Anthropic Directory 등에 공개된 원격 서버를 claude mcp add로 바로 붙인다. 인증·스키마를 다시 만들 이유가 없다
사내 배포 승인 절차, 자체 지식 베이스처럼 팀 고유 업무자체 서버공개 서버가 없는 영역이다. 공식 mcp-server-dev 플러그인으로 뼈대를 만들 수 있다
이미 CLI가 있는 시스템(예: gh)CLI부터 검토모범 사례 문서는 CLI가 있으면 그것이 가장 쉬운 길인 경우가 많다고 본다

연결 전에 서버를 신뢰할 수 있는지 확인한다. 외부 콘텐츠를 가져오는 서버는 프롬프트 인젝션 위험이 있다.

05

리소스: "무엇이 있는지"를 먼저 보여 주기

Resources as catalogs

MCP 사양에서 도구(tool)는 모델이 판단해 호출하는 것이고, 리소스(resource)는 URI로 식별되는 읽기용 데이터로 호스트 애플리케이션이 어떻게 노출할지 정한다. 클라이언트는 resources/list로 목록을, resources/read로 내용을, resources/templates/list로 매개변수형 URI 템플릿을 받는다. 서버는 listChanged·subscribe 기능을 선택적으로 선언한다.

카탈로그 없이
search_runbooks("db") # 0건 search_runbooks("database")# 3건, 그중 하나? search_runbooks("postgres")# 또 다른 이름

무엇이 있는지 몰라 추측성 검색을 반복한다.

카탈로그 리소스로
runbook://index → 런북 27개의 제목·담당 팀·URI schema://warehouse/orders → 테이블 컬럼·타입

목록을 한 번 보고 필요한 항목만 읽는다.

Claude Code에서는 프롬프트에 @를 입력하면 연결된 서버의 리소스가 파일과 함께 자동완성에 나오고, @ops:runbook://index처럼 참조하면 첨부로 자동으로 가져온다. 서버가 리소스를 지원하면 Claude가 직접 쓸 수 있는 ListMcpResourcesTool · ReadMcpResourceTool도 제공된다.

리소스로 둘까, 도구로 둘까
  • 이슈 요약 목록, 문서 트리, DB 스키마처럼 "무엇이 있는지" 보여 주는 읽기용 데이터 → 리소스
  • 조건을 받아 질의하거나 상태를 바꾸는 동작 → 도구
  • 함정: 카탈로그를 "목록 조회 도구" 하나로만 두면 에이전트가 그 도구를 부를 이유를 먼저 찾아야 한다. 리소스는 목록 자체를 맥락으로 건넨다.

시험 함정 · 흔한 오해

오해--scope 없이 추가한 서버는 .mcp.json에 쓰여 팀원도 받는다.
사실기본값은 local이다. ~/.claude.json의 현재 프로젝트 항목에 저장되고 공유되지 않으며, 다른 저장소에서는 보이지 않는다.
오해같은 이름의 서버가 local과 project에 있으면 두 정의의 필드가 합쳐진다.
사실최우선 출처(local)의 항목 전체만 쓰고, 필드를 병합하지 않는다.
오해프로젝트 MCP 서버는 .claude/settings.json의 mcpServers나 .claude/mcp.json에 넣으면 된다.
사실settings.json은 mcpServers 키를 읽지 않는다. 프로젝트 서버는 저장소 루트의 .mcp.json, 그 안의 mcpServers 키에 둔다.
오해MCP 서버를 연결하면 에이전트가 그 도구를 내장 도구보다 먼저 쓴다.
사실모든 도구가 같은 후보일 뿐이다. 선택을 가르는 것은 도구 설명(과 tool search에서는 설명 앞부분의 검색어)이다.
