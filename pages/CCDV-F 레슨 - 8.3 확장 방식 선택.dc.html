Claude 확장 방식 고르기: 내장 도구·커스텀 도구·스킬·MCP

Claude가 할 수 있는 일을 늘리는 방법은 여러 가지다. 내장 도구, 직접 만든 커스텀 도구, MCP 서버, 스킬, CLAUDE.md, 훅, 플러그인. 이것들은 서로 대체재가 아니라 각자 다른 문제를 푸는 층이다. 시험은 요구 사항 한 줄을 주고 어느 층에 넣어야 하는지 묻는다. 판단의 출발점은 간단하다. 내장 도구로 되는 일은 내장 도구로 하고, 외부 서비스는 연결(MCP)로, 반복되는 절차와 노하우는 스킬로, 기존 통합이 없는 사내 동작만 커스텀 도구로 만든다.

습득 포인트
  • Anthropic이 스키마를 정의한 클라이언트 도구(bash·text_editor)와 Anthropic이 실행하는 서버 도구를 구분한다
  • Agent SDK에서 커스텀 도구를 인프로세스 MCP 서버로 등록하는 방법과 그 도구를 쓸 상황을 안다
  • 스킬의 3단계 로딩(메타데이터 → SKILL.md → 참조 파일·스크립트)과 단계별 토큰 비용을 설명한다
  • MCP(연결)와 스킬(절차·지식)을 함께 쓰는 설계와, 기존 MCP 서버를 재사용하는 판단을 내린다
  • CLAUDE.md·스킬·MCP·서브에이전트·훅·플러그인을 요구 사항에 맞게 고른다
01

내장 도구 먼저, 도메인 동작은 커스텀 도구로

Built-in tools first

Claude Code와 Agent SDK에는 파일 읽기·편집, 검색, 명령 실행, 웹 접근을 위한 내장 도구(Read, Edit, Write, Glob, Grep, Bash, WebFetch, WebSearch 등)가 있고, 문서는 이것들이 대부분의 코딩 작업을 감당한다고 설명한다. 파일을 읽는 도구를 새로 만들 이유는 거의 없다.

Messages API에서 직접 앱을 만들 때도 같은 원리다. 셸 실행이나 파일 편집처럼 흔한 작업에는 Anthropic이 스키마를 공개한 도구를 쓴다. 이 스키마는 학습되어 있어서 Claude가 같은 기능의 커스텀 도구보다 더 안정적으로 호출한다.

도구스키마 작성실행 주체앱의 일
text_editor, bash, memory, computer, browserAnthropic여러분의 앱tool_use를 받아 실제로 파일을 고치거나 명령을 돌리고 tool_result를 돌려준다
web_search, web_fetch, code_execution, tool_searchAnthropicAnthropic요청에서 켜고 결과를 읽는다
사용자 정의 도구여러분여러분의 앱사내 로직·내부 API·독점 데이터를 연결한다
구분 기준 한 줄

'스키마를 누가 썼나'와 '누가 실행하나'는 다른 질문이다. text_editor는 Anthropic이 스키마를 썼지만 클라이언트 도구라서 파일 쓰기는 여러분의 코드가 한다. 실행을 Anthropic이 맡는 것은 서버 도구뿐이다.

02

Agent SDK의 커스텀 도구: 인프로세스 MCP 서버

Custom tools in the Agent SDK

내장 도구로 안 되고, 연결할 기존 MCP 서버도 없는 사내 시스템이라면 커스텀 도구를 만든다. Agent SDK에서는 도구를 tool()(TypeScript) 또는 @tool(Python)로 정의하고, createSdkMcpServer·create_sdk_mcp_server로 감싸 mcpServers에 넘긴다. 이 서버는 별도 프로세스가 아니라 앱 프로세스 안에서 돈다.

from typing import Annotated, Any from claude_agent_sdk import (tool, create_sdk_mcp_server, ClaudeAgentOptions) @tool("get_leave_balance", "Return remaining annual-leave days for one employee. " "Use only for current-year balances.", {"employee_id": Annotated[str, "HR id such as E-10293"]}) async def get_leave_balance(args: dict[str, Any]) -> dict[str, Any]: try: days = await hr_client.balance(args["employee_id"]) except HrUnavailable as e: return {"content": [{"type": "text", "text": f"HR service unavailable: {e}. Try later."}], "is_error": True} # Claude가 읽을 오류를 직접 쓴다 return {"content": [{"type": "text", "text": f"{days} days left"}]} hr = create_sdk_mcp_server(name="hr", version="1.0.0", tools=[get_leave_balance]) options = ClaudeAgentOptions( mcp_servers={"hr": hr}, allowed_tools=["mcp__hr__get_leave_balance"], )
요소요점
이름·설명·입력 스키마·핸들러도구를 이루는 네 부분. Claude는 설명을 읽고 언제 부를지 정한다
도구 이름mcp__{server}__{tool}. allowedTools에 이 이름을 넣으면 확인 없이 실행된다
오류잡히지 않은 예외도 루프를 멈추지 않고 원시 메시지로 전달된다. isError·is_error로 직접 쓰면 다음에 할 일까지 알려 줄 수 있다
annotationsreadOnlyHint: true면 다른 읽기 전용 도구와 병렬 호출될 수 있다. 메타데이터일 뿐 강제력은 없다
도구가 많아질 때tool search가 기본으로 켜져 있어, 이름만 목록에 두고 전체 스키마는 필요할 때 불러온다

커스텀 도구를 더할 때 내장 도구를 어떻게 남길지도 함께 정한다. 문서는 두 층을 구분한다. 가용성은 도구가 Claude의 컨텍스트에 보이느냐, 권한은 시도한 호출이 승인되느냐다.

옵션층효과
tools: ["Read", "Grep"]가용성나열한 내장 도구만 컨텍스트에 남는다. MCP 도구에는 영향이 없다
tools: []가용성내장 도구를 모두 빼고 MCP 도구(커스텀 도구 포함)만 쓰게 한다
allowedTools권한나열한 도구는 확인 없이 실행. 나머지는 남아서 권한 흐름을 탄다
disallowedTools둘 다이름만 쓰면 컨텍스트에서 제거, Bash(rm *) 같은 범위 규칙은 도구를 남기고 일치하는 호출만 거부
03

스킬: 필요할 때만 로드되는 노하우

Progressive disclosure

스킬(Agent Skills)은 지시문·메타데이터·선택적 리소스(스크립트·템플릿·참조 문서)를 묶은 파일시스템 기반 디렉터리다. 매번 같은 안내를 프롬프트에 붙이는 대신 스킬로 만들어 두면 Claude가 관련 있을 때 꺼내 쓴다. 핵심은 단계적 공개(progressive disclosure)다.

단계로드 시점토큰 비용내용
1 · 메타데이터항상 (시작 시 시스템 프롬프트)스킬당 약 100YAML 프런트매터의 name과 description
2 · 지시문스킬이 트리거될 때5k 미만SKILL.md 본문
3 · 리소스·코드필요할 때읽기 전까지 0참조 파일은 읽을 때 로드. 스크립트는 bash로 실행되고 출력만 컨텍스트에 들어간다
--- name: contract-review description: Flags risky clauses in supplier contracts and summarizes obligations. Use when the user shares a contract, NDA, or MSA, or asks about liability or termination terms. --- # Contract review 1. Read the whole contract before commenting. 2. For tracked-change edits, follow REDLINE_GUIDE.md.
① STARTUP
모든 스킬의 이름·설명만 시스템 프롬프트에
→
② REQUEST
"이 공급 계약의 위험 조항을 요약해 줘"
→
③ READ SKILL.md
설명과 맞으므로 bash로 SKILL.md를 읽는다
→
④ SKIP
편집 요청이 아니므로 REDLINE_GUIDE.md는 읽지 않는다
→
⑤ FINISH
SKILL.md 지시대로 작업을 마친다
시험 판단 축
  • Claude가 요청과 대조하는 것은 프런트매터의 description이다. 무엇을 하는지와 언제 써야 하는지를 함께 써야 트리거된다 (API 기준 최대 1,024자, name은 소문자·숫자·하이픈 최대 64자)
  • 스킬을 많이 설치해도 시작 시 비용은 '스킬 수 × 약 100토큰'이다. 20개면 약 2,000토큰
  • 번들 파일은 읽기 전까지, 스크립트 코드는 끝까지 컨텍스트를 쓰지 않는다. 길이가 아니라 읽은 파일과 출력이 비용이다
  • Claude Code에서 스킬은 /skill-name으로 직접 부를 수도 있다. 부작용이 있는 절차는 disable-model-invocation: true로 사람만 부르게 하고, 그러면 설명도 컨텍스트에 올라가지 않는다
04

스킬이 동작하는 곳과 신뢰

Where skills run, and whom to trust

스킬은 Claude가 파일시스템과 bash를 쓸 수 있는 실행 환경을 전제로 한다. 같은 스킬이라도 쓰는 곳마다 올리는 방법과 실행 환경이 다르고, 표면 사이에 자동으로 동기화되지 않는다.

표면스킬을 두는 방법실행 환경·공유 범위
Claude Code~/.claude/skills/(개인) 또는 .claude/skills/(프로젝트)에 디렉터리와 SKILL.md를 둔다. 업로드가 필요 없다사용자 컴퓨터와 같은 네트워크 접근. 프로젝트 스킬은 커밋해 팀과 공유하고, 플러그인으로도 배포한다
Claude APISkills API(/v1/skills)로 올리고 container의 skill_id로 지정한다. code execution 도구가 필요하다네트워크 접근 없음, 실행 중 패키지 설치 불가. 워크스페이스 전체 공유
claude.ai설정에서 zip으로 올린다(코드 실행이 켜진 유료 플랜)사용자 개인 단위. 조직 전체 배포나 관리자 중앙 관리는 없다
스킬은 소프트웨어 설치처럼 다룬다

스킬은 지시문과 코드로 Claude에게 새 능력을 주므로, 악의적인 스킬은 설명과 다른 방식으로 도구를 부르거나 코드를 실행하게 만들 수 있다. 직접 만들었거나 Anthropic에서 받은 신뢰할 수 있는 출처의 스킬만 쓰고, 그렇지 않으면 번들된 파일 전부(SKILL.md, 스크립트, 리소스)를 검토한다. 외부 URL에서 데이터를 가져오는 스킬은 특히 위험하다.

05

MCP는 연결, 스킬은 절차

MCP and skills work together

MCP와 스킬은 양자택일이 아니다. 공식 문서는 둘을 이렇게 나눈다. MCP는 외부 시스템을 위한 전용 도구를 주고 연결과 인증을 서버가 처리한다. 스킬은 그 도구를 잘 쓰는 법, 즉 팀의 스키마·쿼리 패턴·메시지 형식 같은 지식과 /<name>으로 부르는 워크플로를 준다.

MCP 서버가 맡는 것

데이터 웨어하우스 접속, OAuth 로그인, run_query·list_views 같은 도구. "무엇을 할 수 있는가"

스킬이 맡는 것

"항상 tenant_id로 거른다, 원본 테이블 대신 승인된 뷰를 쓴다, 결과는 1만 행 이하". "어떻게 해야 하는가"

재발명

이슈 트래커가 이미 공식 원격 MCP 서버와 OAuth 로그인을 제공하는데, REST API를 직접 부르는 커스텀 도구를 새로 만든다. 인증·페이지네이션·오류 처리를 다시 짜고 유지해야 한다.

재사용

기존 MCP 서버를 연결하고 필요한 도구만 allowedTools로 승인한다. 팀 규칙(라벨 체계, 제목 형식)이 있으면 그것만 스킬로 더한다.

반대로 기존 통합이 없는 독점 사내 서비스라면 연결할 서버가 없으니 직접 만든다. Agent SDK 앱 안에서만 쓸 것이면 02의 인프로세스 커스텀 도구로 충분하고, 여러 MCP 호스트에서 재사용할 것이면 독립 MCP 서버로 만드는 편이 맞다.

조합작동 방식예
스킬 + MCPMCP가 연결을, 스킬이 잘 쓰는 법을 준다MCP로 DB에 접속하고, 스킬에 스키마와 쿼리 패턴을 적는다
스킬 + 서브에이전트스킬이 병렬 작업용 서브에이전트를 띄운다/audit가 보안·성능·스타일 서브에이전트를 격리된 컨텍스트에서 돌린다
CLAUDE.md + 스킬항상 지킬 규칙은 CLAUDE.md, 참조 자료는 필요할 때 스킬로CLAUDE.md에는 "API 규약을 따른다", 스킬에는 규약 전문
훅 + MCP훅이 MCP를 통해 외부 동작을 일으킨다중요 파일이 바뀌면 편집 후 훅이 채팅 알림을 보낸다
06

CLAUDE.md·스킬·MCP·서브에이전트·훅·플러그인

Match the feature to the goal
기능하는 일로드·비용이럴 때
CLAUDE.md매 세션 들어가는 지속 컨텍스트세션 시작 시 전체, 모든 요청에 비용"pnpm을 쓴다", "커밋 전 테스트" 같은 항상 지킬 규칙
스킬지식·참조 자료·호출 가능한 워크플로설명은 시작 시, 본문은 쓸 때가끔 필요한 참조 자료, /deploy 같은 반복 절차
MCP외부 서비스 연결시작 시 도구 이름, 스키마는 필요할 때(tool search)DB 조회, 채팅 서비스 게시, 브라우저 제어
서브에이전트격리된 컨텍스트에서 돌고 요약만 반환메인 세션과 분리많은 파일을 읽는 조사, 병렬 작업
훅수명 주기 이벤트에서 스크립트 등을 실행출력이 없으면 0매번 반드시 일어나야 하는 일(편집 후 린트, 위험 명령 차단)
플러그인스킬·훅·서브에이전트·MCP 서버를 묶는 패키지 층담긴 구성 요소를 따른다같은 설정을 여러 저장소에서 재사용하거나 배포할 때
문서가 주는 '추가 신호'

같은 실수를 두 번 하면 CLAUDE.md, 같은 프롬프트를 계속 치거나 같은 절차를 세 번째 붙여 넣으면 스킬, Claude가 못 보는 브라우저 탭에서 계속 데이터를 복사해 오면 MCP, 곁가지 작업이 대화를 출력으로 채우면 서브에이전트, 묻지 않고 매번 일어나야 하면 훅, 두 번째 저장소에 같은 설정이 필요하면 플러그인.

CLAUDE.md에 넣으면 손해

교대 인수인계 때만 쓰는 12단계 절차. 매 세션·매 요청 비용을 내면서 대부분의 작업에는 쓰이지 않는다. 문서 권장대로 CLAUDE.md는 200줄 이하로 유지한다.

스킬이 맞는 이유

필요할 때만 본문이 로드되고, /handoff처럼 이름으로 바로 부를 수 있다. 반대로 ".env는 절대 수정하지 말 것"처럼 반드시 지켜야 하는 규칙은 지시문이 아니라 훅으로 강제한다.

시험 함정 · 흔한 오해

오해bash와 text_editor는 Anthropic이 스키마를 정의했으니 Anthropic이 실행한다.
사실둘 다 클라이언트 도구다. 실행과 결과 반환은 여러분의 앱이 한다. Anthropic이 실행하는 것은 서버 도구다.
오해스킬을 많이 설치하면 시작할 때 컨텍스트 창이 가득 찬다.
사실트리거 전까지는 스킬마다 이름과 설명(약 100토큰)만 올라간다.
오해스킬에 넣은 스크립트는 코드 길이만큼 컨텍스트를 쓴다.
사실스크립트는 bash로 실행되고 코드는 컨텍스트에 들어가지 않는다. 출력만 토큰을 쓴다.
오해MCP와 스킬은 같은 문제를 푸는 대안이니 하나만 고르면 된다.
사실MCP는 연결과 도구, 스킬은 그 도구를 쓰는 지식과 절차다. 함께 쓰도록 설계되었다.
오해공식 MCP 서버가 있어도 커스텀 도구로 다시 만드는 편이 통제하기 좋다.
사실기존 서버가 연결·인증을 이미 처리한다. 다시 만들면 유지 보수만 늘어난다. 필요한 도구만 승인한다.
