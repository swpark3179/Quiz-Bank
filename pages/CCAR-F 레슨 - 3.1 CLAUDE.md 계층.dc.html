CLAUDE.md 계층·범위·모듈화

managed · user · project · local · 하위 디렉터리 지연 로드 · @path 가져오기 · .claude/rules/ · /context · /memory

참고 레슨 · CertSafari 3.1  |  출제 도메인: 도메인 3 · Claude Code Configuration & Workflows (20%)

3.1 CLAUDE.md3.2 명령·스킬3.3 경로별 규칙3.4 플랜 모드3.5 반복 개선3.6 CI/CD

CLAUDE.md는 Claude가 세션을 시작할 때 읽는 지침용 마크다운 파일이다. 같은 내용이라도 어디에 두느냐에 따라 받는 사람과 로드 시점이 달라진다. 시험은 "왜 이 팀원에게는 지침이 안 먹히나" 같은 계층 진단과, 커진 파일을 나누는 방법을 묻는다. 팀이 함께 따라야 할 지침은 저장소에 커밋되는 위치에, 나만의 선호는 홈 디렉터리나 CLAUDE.local.md에 둔다.

습득 포인트
  • user(~/.claude/CLAUDE.md) · project(./CLAUDE.md, ./.claude/CLAUDE.md) · 하위 디렉터리 CLAUDE.md의 위치와 범위
  • user 수준 지침은 버전 관리로 팀원에게 전달되지 않는다는 점과 그로 인한 증상 진단
  • @path 가져오기로 패키지별 CLAUDE.md에 필요한 표준 문서만 포함하기
  • 단일 CLAUDE.md를 .claude/rules/의 주제별 파일로 나누기
  • /memory와 /context로 어떤 메모리 파일이 있고 무엇이 로드됐는지 확인하기
01

위치가 곧 받는 사람이다

Where a file lives decides who gets it
범위위치받는 사람넣을 내용 (예)
Managed policyOS별 관리 경로 (예: Linux /etc/claude-code/CLAUDE.md)그 머신의 모든 사용자회사 보안·컴플라이언스 안내
User~/.claude/CLAUDE.md나 (모든 프로젝트)"설명은 짧게, 커밋 메시지는 영어로"
Project./CLAUDE.md 또는 ./.claude/CLAUDE.md저장소를 쓰는 팀 (커밋)빌드·테스트 명령, 아키텍처, 팀 규칙
Local./CLAUDE.local.md (.gitignore에 추가)나 (이 프로젝트)내 샌드박스 URL, 내가 쓰는 테스트 계정
하위 디렉터리apps/search/CLAUDE.md 등그 디렉터리 파일을 다룰 때 (커밋 시 팀)그 서비스만의 스택 규칙
시험 가이드 표현 vs 현재 문서

가이드는 user · project · directory 세 층으로 설명한다. 현재 문서에는 여기에 Managed policy(조직 배포, claudeMdExcludes로도 제외할 수 없음)와 개인용 CLAUDE.local.md가 더 있고, 개인 규칙 폴더 ~/.claude/rules/도 있다. 시험의 "user vs project" 판단은 그대로 유효하다.

02

무엇이 언제, 어떤 순서로 로드되나

Launch vs on demand · concatenation

Claude Code는 실행한 디렉터리와 그 위의 모든 상위 디렉터리에서 CLAUDE.md와 CLAUDE.local.md를 찾아 시작 시 로드한다. 실행 위치 아래 하위 디렉터리의 CLAUDE.md는 시작 시 로드되지 않고, Claude가 그 디렉터리의 파일을 읽거나 쓰거나 편집할 때 로드된다.

실행
~/shop/apps/checkout
에서 claude 시작
→
시작 시 로드
~/shop/CLAUDE.md
+ checkout/CLAUDE.md
→
작업 중 로드
checkout/api/ 파일을 읽으면
checkout/api/CLAUDE.md
→
로드 안 됨
형제 디렉터리
apps/search/CLAUDE.md
  • 덮어쓰지 않고 이어 붙인다. 파일시스템 루트 쪽부터 실행 위치 쪽 순서로 연결되므로 실행 위치에 가까운 지침이 나중에 읽힌다. 같은 디렉터리에서는 CLAUDE.local.md가 CLAUDE.md 뒤에 붙는다.
  • 범위별로는 managed → user → project 순으로 컨텍스트에 놓인다. 두 지침이 충돌하면 Claude가 어느 쪽을 따를지 보장되지 않으므로, 충돌 자체를 없애야 한다.
  • CLAUDE.md 내용은 시스템 프롬프트 뒤의 사용자 메시지로 전달되는 컨텍스트이지 강제 설정이 아니다. 반드시 지켜야 할 규칙은 hook이나 권한(permissions.deny)으로 강제한다.
  • 블록 단위 HTML 주석(<!-- ... -->)은 컨텍스트에 넣기 전에 제거되어 관리자용 메모로 쓸 수 있다.
03

계층 문제 진단하기

Why does a teammate miss the rule?

시나리오: 리드 개발자는 "스키마를 바꾸면 make migrate-check를 통과한 뒤 커밋"이라는 지침을 오래 써 왔고, 그의 Claude는 늘 이를 지킨다. 새로 합류한 팀원의 Claude는 이 절차를 전혀 모른다.

원인 · user 수준에 있었다
~/.claude/CLAUDE.md # 리드의 홈 디렉터리 - 스키마 변경 후 make migrate-check

홈 디렉터리 파일은 저장소에 없으므로 클론해도 전달되지 않는다.

해결 · project 수준으로 옮겨 커밋
./CLAUDE.md 또는 .claude/rules/db.md - 스키마 변경 후 make migrate-check

저장소를 받는 모든 사람의 세션에 들어간다.

확인 도구
명령·기능무엇을 보여 주나
/context현재 컨텍스트 구성. Memory files 목록에서 시작 시 실제로 로드된 CLAUDE.md·rules 파일을 확인한다
/memoryuser·project 범위의 메모리 파일 위치 목록(아직 없는 파일 포함). 선택하면 편집기로 열고, 자동 메모리(auto memory) 켜기·끄기와 폴더 열기도 여기서 한다
InstructionsLoaded hook어떤 지침 파일이 언제·왜 로드됐는지 기록. 지연 로드되는 하위 CLAUDE.md나 경로 규칙 디버깅용
시험 가이드 표현 vs 현재 문서

가이드는 "/memory로 어떤 메모리 파일이 로드됐는지 확인"한다고 적는다. 현재 문서에서 /memory는 파일 위치를 나열하고 열어 편집하는 곳이며, 시작 시 실제로 로드된 파일 확인은 /context를 쓰라고 안내한다. 하위 디렉터리 CLAUDE.md는 지연 로드되므로 시작 직후 /context 목록에 없는 것이 정상이며, 로드되면 터미널에 Loaded 줄이 표시된다.

04

@path 가져오기로 필요한 표준만 포함

Imports for modular CLAUDE.md

CLAUDE.md 안에 @경로를 쓰면 그 파일이 펼쳐져 함께 로드된다. 상대 경로는 작업 디렉터리가 아니라 가져오는 파일의 위치 기준이고, 가져온 파일이 다시 가져오는 재귀는 최대 4단계까지다. 모노레포라면 패키지 담당자가 자기 패키지에 해당하는 표준 문서만 고른다.

# packages/billing/CLAUDE.md — 결제 패키지 담당자가 관리 금액 계산과 오류 응답은 아래 표준을 따른다. - @../../docs/standards/money-handling.md - @../../docs/standards/api-errors.md # packages/web/CLAUDE.md — 프런트엔드 담당자가 관리 - @../../docs/standards/accessibility.md - 경로만 언급하고 가져오지 않을 때는 백틱: `@docs/legacy-notes.md`
  • 경로에 공백이 있으면 공백마다 백슬래시를 붙인다(@Team\ Docs/x.md). 따옴표로 감싸면 가져오지 않는다.
  • 작업 디렉터리 밖을 가리키는 외부 가져오기는 프로젝트에서 처음 만날 때 승인 대화상자가 뜬다. 여러 worktree에서 공유할 개인 지침은 @~/.claude/...처럼 홈 디렉터리 파일을 가져오면 된다.
함정 · 가져오기는 컨텍스트를 줄이지 않는다

가져온 파일은 가져오는 CLAUDE.md와 함께 로드된다. 파일을 정리하는 데는 도움이 되지만 토큰 비용은 그대로다. 컨텍스트를 줄이려면 일부 파일에서만 필요한 내용을 경로 한정 규칙(3.3)이나 스킬(3.2)로 옮긴다. 참고로 가이드가 말하는 "@import 문법"은 문서상 @path/to/import 형태이며 import 키워드는 없다.

05

거대한 CLAUDE.md를 .claude/rules/로 나누기

Topic files instead of one monolith

문서는 CLAUDE.md 한 파일을 200줄 미만으로 유지하라고 권한다. 길어질수록 컨텍스트를 더 쓰고 지침 준수율이 떨어진다. .claude/rules/에 주제 하나당 파일 하나(testing.md, api-conventions.md, release.md …)를 두면 팀이 나눠 관리하기 쉽다. 하위 폴더까지 재귀적으로 .md를 찾는다.

repo/ ├── CLAUDE.md # 빌드 명령·핵심 규칙만 └── .claude/ └── rules/ ├── testing.md # paths 없음 → 매 세션 로드 ├── api-conventions.md └── frontend/ └── components.md # paths 지정 → 일치 파일 작업 시만 (3.3)
CLAUDE.md
매 세션 로드. 빌드·테스트 명령, 모든 작업에 해당하는 규칙.
.claude/rules/
paths가 없으면 .claude/CLAUDE.md와 같은 우선순위로 매 세션 로드. 있으면 일치 파일을 다룰 때만.
Skill
호출되거나 관련 있다고 판단될 때만 본문 로드. 절차·참고 자료용.
분리 판단 축
  • paths 없이 나누기만 하면 관리가 쉬워질 뿐 매 세션 로드량은 같다
  • 일부 파일 유형에만 해당하는 규칙 → paths를 단 규칙 파일
  • 여러 단계로 된 절차나 가끔 필요한 참고 자료 → 스킬
  • 다른 팀 패키지의 CLAUDE.md가 끼어든다면 claudeMdExcludes(예: .claude/settings.local.json)로 제외한다. 단 managed CLAUDE.md는 제외되지 않는다
  • 개인 규칙은 ~/.claude/rules/. 프로젝트 규칙보다 먼저 로드되지만 서로 덮어쓰지 않으므로 충돌하지 않게 유지한다

시험 함정 · 흔한 오해

오해하위 디렉터리 CLAUDE.md가 상위 CLAUDE.md를 덮어쓴다.
사실발견된 파일은 모두 이어 붙는다. 실행 위치에 가까운 파일이 나중에 읽힐 뿐이며, 충돌 시 어느 쪽이 따라질지는 보장되지 않는다.
오해@path로 쪼개면 컨텍스트 사용량이 줄어든다.
사실가져온 파일은 함께 로드되므로 줄지 않는다. 줄이려면 경로 한정 규칙이나 스킬로 옮긴다.
오해CLAUDE.md에 "절대 .env를 수정하지 말 것"이라고 쓰면 그 동작이 차단된다.
사실CLAUDE.md는 강제력이 없는 컨텍스트다. 차단은 PreToolUse hook이나 권한 deny 규칙으로 한다.
오해세션 시작 직후 /context에 하위 디렉터리 CLAUDE.md가 없으면 파일 위치가 잘못된 것이다.
사실하위 디렉터리 파일은 지연 로드라 원래 시작 목록에 없다. 그 디렉터리의 파일을 Claude가 읽으면 로드된다.
