## 문제 1
### **팀장의 Claude는 "API 응답에 항상 `request_id`를 포함"을 지키지만, 같은 저장소를 클론한 신입의 Claude는 지키지 않는다. 팀장은 이 지침을 `~/.claude/CLAUDE.md`에 적었다. 올바른 조치는?**

| 보기 | 설명 |
|------|------|
| 1. 신입에게 팀장의 홈 디렉터리 파일을 복사해 주고 끝낸다 | |
| 2. 지침 앞에 IMPORTANT를 붙인다 | |
| 3. 신입의 `CLAUDE.local.md`에 같은 내용을 적게 한다 | |
| **4. 지침을 프로젝트 CLAUDE.md(또는 `.claude/rules/`)로 옮겨 커밋한다** | |

**정답: 4.**

**해설:**

> 📘 레슨 3.1 · CLAUDE.md 계층 — 계층 진단

> **핵심:** 팀이 모두 지켜야 할 규칙은 버전 관리로 공유되는 **project 수준** 에 둡니다. 사람마다 결과가 다르면 문구보다 위치(scope)를 먼저 의심합니다.

1. **오답** - 팀장의 홈 디렉터리 파일을 신입 한 명에게 복사해 주면 당장은 맞아도, 이후 합류자나 팀장이 규칙을 고칠 때마다 다시 어긋납니다. 사람마다 따로 관리하는 구조가 문제의 원인입니다.
2. **오답** - 신입의 세션에는 이 지침이 아예 로드되지 않습니다. 없는 문장 앞에 IMPORTANT를 붙여도 효과가 없고, 위치 문제는 그대로입니다.
3. **오답** - `CLAUDE.local.md` 는 "나 · 이 프로젝트" 범위의 개인 파일이고 `.gitignore` 에 넣어 커밋하지 않습니다. 결국 사람마다 따로 관리하게 되어 다시 어긋납니다.
4. **정답** - `~/.claude/CLAUDE.md` 는 그 사람 머신의 모든 프로젝트에 적용되지만 저장소에는 들어가지 않습니다. 프로젝트 `./CLAUDE.md`(또는 `./.claude/CLAUDE.md`, `.claude/rules/`)로 옮겨 커밋하면 저장소를 받는 모든 사람의 세션에 자동으로 들어갑니다.

## 문제 2
### **이 프로젝트에서만 쓰는 내 개인 스테이징 URL을 Claude에게 알려 두고 싶다. 팀 저장소에는 올리고 싶지 않다. 알맞은 위치는?**

| 보기 | 설명 |
|------|------|
| 1. `./CLAUDE.md` | |
| **2. `./CLAUDE.local.md` (`.gitignore`에 추가)** | |
| 3. `~/.claude/CLAUDE.md` | |
| 4. managed policy CLAUDE.md | |

**정답: 2.**

**해설:**

> 📘 레슨 3.1 · CLAUDE.md 계층 — 개인 · 프로젝트 한정

> **핵심:** "나만, 이 프로젝트에서만" 쓸 지침은 `.gitignore` 에 넣은 **`./CLAUDE.local.md`** 에 둡니다.

1. **오답** - `./CLAUDE.md` 는 커밋되어 팀 전체와 공유되는 project 지침입니다. 개인 스테이징 URL이 팀 저장소에 올라갑니다.
2. **정답** - `CLAUDE.local.md` 는 프로젝트 루트에 두는 개인용 프로젝트 지침으로, `CLAUDE.md` 와 함께 로드되고 같은 디렉터리에서는 그 뒤에 붙습니다. 문서는 커밋되지 않도록 `.gitignore` 에 추가하라고 안내합니다. 여러 worktree에서 같은 개인 지침이 필요하면 `@~/.claude/...` 처럼 홈 디렉터리 파일을 가져오는 방법도 있습니다.
3. **오답** - `~/.claude/CLAUDE.md` 는 공유되지는 않지만 내 **모든** 프로젝트에 적용됩니다. 이 프로젝트 전용 URL을 두기에는 범위가 너무 넓습니다.
4. **오답** - managed policy CLAUDE.md는 IT/DevOps가 OS 관리 경로에 배포해 그 머신의 모든 사용자에게 적용하는 조직 지침입니다. 개인 설정을 둘 곳이 아닙니다.

## 문제 3
### **`~/shop/CLAUDE.md`, `~/shop/apps/checkout/CLAUDE.md`, `~/shop/apps/search/CLAUDE.md`가 있다. `~/shop/apps/checkout`에서 Claude Code를 시작했다. 시작 시점에 로드되는 것은?**

| 보기 | 설명 |
|------|------|
| 1. 세 파일 모두 | |
| 2. checkout의 파일만 — 가장 가까운 하나가 나머지를 대체한다 | |
| **3. `~/shop/CLAUDE.md`와 checkout의 CLAUDE.md** | |
| 4. `~/shop/CLAUDE.md`만 | |

**정답: 3.**

**해설:**

> 📘 레슨 3.1 · CLAUDE.md 계층 — 로드 시점

> **핵심:** 시작 시에는 **실행 디렉터리와 그 상위 디렉터리** 의 CLAUDE.md가 이어 붙어 로드됩니다. 형제 디렉터리는 위도 아래도 아니어서 로드되지 않습니다.

1. **오답** - `apps/search/` 는 실행 위치(`apps/checkout`)의 상위도 하위도 아닌 형제 디렉터리입니다. 시작 시 로드되지 않고, Claude가 그 안의 파일을 다루기 전까지는 들어오지 않습니다.
2. **오답** - 가까운 파일이 나머지를 대체하지 않습니다. 발견된 파일은 모두 이어 붙고, 파일시스템 루트 쪽부터 실행 위치 쪽 순서로 놓여 가까운 지침이 나중에 읽힐 뿐입니다.
3. **정답** - 상위의 `~/shop/CLAUDE.md` 와 실행 위치의 `apps/checkout/CLAUDE.md` 가 시작 시 함께 로드됩니다. 실행 위치 아래 하위 디렉터리의 CLAUDE.md는 Claude가 그 디렉터리의 파일을 읽기·쓰기·편집할 때 로드됩니다.
4. **오답** - 실행한 디렉터리 자신의 CLAUDE.md도 시작 시 로드됩니다. 지연 로드는 실행 위치 **아래** 의 파일에만 해당합니다.

## 문제 4
### **`packages/billing/CLAUDE.md` 안의 `@../../docs/standards/money.md`는 어느 경로를 기준으로 해석되는가?**

| 보기 | 설명 |
|------|------|
| **1. 가져오기를 적은 파일(`packages/billing/CLAUDE.md`)의 위치** | |
| 2. Claude Code를 실행한 작업 디렉터리 | |
| 3. 사용자 홈 디렉터리 | |
| 4. git 저장소 루트 | |

**정답: 1.**

**해설:**

> 📘 레슨 3.1 · CLAUDE.md 계층 — @path 해석

> **핵심:** `@path` 가져오기의 상대 경로는 작업 디렉터리가 아니라 **가져오기를 적은 파일의 위치** 를 기준으로 해석됩니다.

1. **정답** - 문서는 상대 경로가 작업 디렉터리가 아니라 가져오기를 포함한 파일 기준으로 해석된다고 명시합니다. 그래서 `packages/billing/` 에서 두 단계 올라간 저장소 루트의 `docs/standards/money.md` 를 가리키고, 어디서 실행하든 같은 파일이 됩니다. 가져온 파일이 다시 가져오는 재귀는 최대 4단계까지입니다.
2. **오답** - 작업 디렉터리 기준이라면 실행 위치에 따라 가리키는 파일이 달라져 모노레포에서 쓸 수 없습니다. 문서가 명시적으로 부정하는 해석입니다.
3. **오답** - 홈 디렉터리 기준 경로는 `@~/.claude/...` 처럼 `~` 를 직접 써야 합니다. 상대 경로가 홈 기준으로 바뀌지는 않습니다.
4. **오답** - git 저장소 루트를 기준으로 삼는 규칙은 없습니다. 이 예에서는 결과적으로 루트 아래 파일을 가리키지만, 그것은 `packages/billing/` 에서 `../../` 로 올라갔기 때문입니다.

## 문제 5
### **600줄짜리 CLAUDE.md를 `.claude/rules/` 아래 주제별 파일 8개로 나눴다. 어느 파일에도 `paths` frontmatter는 없다. 컨텍스트 측면의 결과는?**

| 보기 | 설명 |
|------|------|
| 1. 관련 주제가 나올 때만 해당 파일이 로드되어 크게 줄어든다 | |
| **2. 모두 매 세션 시작 시 로드되므로 정리는 쉬워졌지만 로드량은 거의 같다** | |
| 3. rules 파일은 `/memory`로 열 때만 로드된다 | |
| 4. 규칙 파일은 하위 디렉터리 CLAUDE.md보다 늦게 로드되어 무시된다 | |

**정답: 2.**

**해설:**

> 📘 레슨 3.1 · CLAUDE.md 계층 — rules로 분리

> **핵심:** `paths` 가 **없는** 규칙 파일은 CLAUDE.md처럼 매 세션 로드됩니다. 나누면 관리는 쉬워지지만 로드량은 거의 같습니다.

1. **오답** - 관련 주제가 나올 때만 로드되는 조건부 동작은 `paths` frontmatter를 지정해야 일어납니다. 이 경우 여덟 파일 모두 조건이 없습니다.
2. **정답** - `paths` 가 없는 규칙은 `.claude/CLAUDE.md` 와 같은 우선순위로 시작 시 로드됩니다. 주제별로 나눠 팀이 관리하기 쉬워지지만 컨텍스트에 들어가는 총량은 그대로입니다. 줄이려면 일부 파일에만 해당하는 내용을 `paths` 규칙이나 스킬로 옮겨야 합니다.
3. **오답** - `/memory` 는 메모리 파일 위치를 나열하고 편집기로 여는 명령일 뿐, 규칙 로드를 결정하지 않습니다.
4. **오답** - 규칙 파일은 무시되지 않습니다. 하위 디렉터리 CLAUDE.md와 로드 순서가 다를 수는 있어도, 발견된 지침은 서로 덮어쓰지 않고 모두 컨텍스트에 들어갑니다.

## 문제 6
### **세션마다 Claude의 행동이 달라, 어떤 CLAUDE.md와 규칙 파일이 이번 세션 시작 시 실제로 로드됐는지 확인하려 한다. 가장 직접적인 방법은?**

| 보기 | 설명 |
|------|------|
| 1. `/init`을 다시 실행한다 | |
| 2. `~/.claude.json`을 연다 | |
| 3. 저장소의 모든 CLAUDE.md를 Glob으로 찾는다 | |
| **4. `/context`를 실행해 Memory files 목록을 본다 (파일 위치 확인·편집은 `/memory`)** | |

**정답: 4.**

**해설:**

> 📘 레슨 3.1 · CLAUDE.md 계층 — 로드 확인

> **핵심:** 이번 세션 시작 시 **실제로 로드된** 파일은 `/context` 의 **Memory files** 목록으로 확인합니다. `/memory` 는 위치 확인과 편집용입니다.

1. **오답** - `/init` 은 코드베이스를 분석해 CLAUDE.md 초안을 만드는 명령입니다. 이미 로드된 파일을 보여 주지 않고 오히려 파일 내용을 바꿀 수 있습니다.
2. **오답** - `~/.claude.json` 은 Claude Code가 스스로 쓰는 앱 상태 파일로, 계정 정보·UI 설정·개인 MCP 서버·프로젝트별 신뢰 상태 등을 담습니다. 어떤 CLAUDE.md가 로드됐는지는 여기서 알 수 없습니다.
3. **오답** - Glob으로 찾으면 디스크에 존재하는 파일 목록만 나옵니다. 하위 디렉터리 CLAUDE.md처럼 존재하지만 아직 로드되지 않은 파일과, 실제로 로드된 파일을 구분해 주지 않습니다.
4. **정답** - 문서는 시작 시 로드된 CLAUDE.md·규칙 파일 확인에 `/context` 를 실행해 Memory files 목록을 보라고 안내합니다. `/memory` 는 user·project 범위의 메모리 파일 위치(아직 없는 파일 포함)를 나열하고 편집기로 여는 곳입니다. 하위 디렉터리 CLAUDE.md는 지연 로드라 시작 직후 목록에 없는 것이 정상입니다.

| 4. `~/.claude.json`의 프로젝트 항목 | |

## 문제 9
### **SKILL.md에 `allowed-tools: Bash(git status *) Bash(git diff *)`를 적었다. 이 스킬을 호출한 턴의 동작으로 옳은 것은?**

| 4. 나열한 명령이 사용 가능 목록에서 제거된다 | |

**해설:**

> 📘 레슨 3.2 · 슬래시 명령·스킬 — allowed-tools

## 문제 15
### **규칙에 `paths: ["lib/*.py"]`를 적었는데 `lib/payments/refund.py`를 다룰 때 규칙이 적용되지 않는다. 원인과 고칠 방법은?**

| 2. `paths`는 디렉터리만 받는다 → `lib/`로 바꾼다 | |
| 3. 규칙은 `.py`를 지원하지 않는다 → 루트 CLAUDE.md로 옮긴다 | |
| 4. 패턴을 따옴표로 감싸서 생긴 문제다 → 따옴표를 뺀다 | |

3. **오답** - 규칙 범위는 확장자와 무관하게 glob으로 지정합니다. `.py` 라서 안 되는 제한은 없습니다.

4. **정답** - Explore는 파일 탐색·코드 검색·코드베이스 조사를 위한 읽기 전용 에이전트이고, Claude가 호출할 때 quick(특정 조회), medium(균형 잡힌 탐색), very thorough(종합 분석) 중 하나를 지정합니다. 모델은 기본적으로 메인 대화의 모델을 따릅니다.

> 📘 레슨 3.6 · CI·CD 연동 — 재리뷰
