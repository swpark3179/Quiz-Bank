# 📖 단어장 (vocab)

퀴즈 풀이 중 **단어장 모드**를 켜면, 이 폴더에 등록한 단어가 문제 본문·보기에 나올 때 단어 오른쪽 위에 작은 `°` 표시가 붙습니다. 그 단어를 누르면 바로 옆에 뜻 팝업이 뜹니다.

- 단어장 모드는 **퀴즈 설정 시트**(풀이 도우미 → 단어장 모드)에서 켜고, 풀이 중에는 **헤더 오른쪽 책 아이콘**으로 바로 켜고 끕니다. 마지막 선택은 기기에 기억됩니다.
- 문제 파일과 똑같이 **GitHub 에 커밋하면 앱 재배포 없이 바로 반영**됩니다.

---

## 폴더 구조

```
assets/quiz-data/vocab/
  index.json            # ⭐ 등록 단어 목록 (필수) — 문제에서 찾을 표현과 한 줄 뜻
  escalate.md           # 단어별 상세 설명 (선택) — 파일 이름 = index.json 의 id
  exponential-backoff.md
  _template.md          # 상세 설명 템플릿 (앱이 읽지 않음)
  README.md             # 이 안내 (앱이 읽지 않음)
```

문제의 `config.json` + `*.md` 와 같은 구조입니다. **목록(index.json)에 등록**하고, 필요하면 **단어별 설명(.md)** 을 씁니다.

---

## 1) `index.json` 에 등록

```json
[
  {
    "id": "escalate",
    "word": "escalate",
    "pos": "동사",
    "ipa": "ˈeskəleɪt",
    "meaning": "(상위 담당자에게) 넘기다, 단계를 올려 처리하다",
    "forms": ["escalated", "escalating", "escalation"]
  }
]
```

| 필드 | 필수 | 설명 | 예 |
|------|:----:|------|------|
| `id` | ✅ | 상세 설명 파일 이름 (`vocab/{id}.md`). 소문자·숫자·하이픈만 | `exponential-backoff` |
| `word` | ✅ | 표제어. 팝업 제목이자 문제에서 찾는 기본 표현. 여러 단어로 된 구도 가능 | `exponential backoff` |
| `meaning` | ✅ | 한 줄 뜻. 팝업을 열자마자 크게 보입니다 | `지수 백오프 — …` |
| `pos` | | 품사 | `동사`, `명사구` |
| `ipa` | | 발음 기호 (앞뒤 `/` 없이) | `ˈeskəleɪt` |
| `forms` | | 문제에서 함께 찾을 변형·파생어·다른 표기 | `["escalated", "escalation"]` |

### 문제에서 단어를 찾는 규칙

- **대소문자는 구분하지 않습니다.** `Escalate`, `ESCALATE` 모두 찾습니다.
- **`-s` / `-es` 는 자동**입니다. `escalate` 만 적어도 `escalates` 를 찾습니다.
  그 밖의 변형(`-ed`, `-ing`, `-ion`, 불규칙 변화, 다른 철자)은 `forms` 에 적습니다.
- **긴 표현이 먼저** 맞습니다. `exponential backoff` 를 등록하면 그 구 전체가 한 단어로 표시됩니다.
- **다른 단어의 일부는 표시하지 않습니다.** 앞뒤가 영문자·숫자·하이픈으로 이어지면 건너뜁니다
  (`tune` 은 `fine-tuned` 안에서 표시되지 않음). 한글 조사가 바로 붙은 경우(`fork를`)는 표시합니다.
- 인라인 코드(`` `…` ``)와 코드 블록 속 단어는 표시하지 않습니다.
- 같은 표현을 두 단어에 등록할 수 없습니다 (자동 검사가 막습니다).

## 2) 상세 설명 작성 — `{id}.md` (선택)

상세 설명은 **Markdown** 으로 씁니다.

- 문제 파일과 같은 형식이라 따로 배울 것이 없고, GitHub 에서 바로 미리 볼 수 있습니다.
- 앱이 팝업 안에서 **앱 테마(글꼴·색·간격) 그대로** 그려 화면과 어울립니다. HTML 은 웹뷰가 필요하고 화면과 따로 놀아 쓰지 않습니다.
- 한 번 연 설명은 기기에 저장되어 오프라인에서도 다시 볼 수 있습니다.

파일이 없으면 팝업에 **한 줄 뜻만** 보입니다 (예: `upfront`). 처음엔 `index.json` 만 채우고, 자주 헷갈리는 단어부터 설명을 붙여도 됩니다.

### 템플릿

[`_template.md`](./_template.md) 를 복사해 `{id}.md` 로 저장하고 채웁니다. 필요 없는 구역은 지웁니다.
맨 위는 제목 없이 시작합니다 — 뜻이 하나면 뉘앙스 문단, 여럿이면 번호 목록 중 하나만 남깁니다.

```markdown
뉘앙스를 한두 문장으로 풀어 씁니다. 어떤 상황에서 쓰는 말인지, **핵심**은 굵게 표시합니다.

1. **첫 번째 뜻** — 뜻이 여럿이면 위 문단 대신 번호 목록으로 씁니다
2. **두 번째 뜻** — 문제에 자주 나오는 순서대로

## 문제 속 쓰임
> 문제에 실제로 나온 영어 문장을 옮기고, 해당 단어를 **굵게** 표시합니다.
> 그 문장의 우리말 해석에서도 해당 부분을 **굵게** 표시합니다.

## 함께 쓰는 표현
- **표현 1** : 뜻
- **표현 2** : 뜻

## 비슷한 말 · 반대말
- **비슷한 말** — 차이가 있으면 짧게
- **반대말** — 뜻

## 시험 포인트
정답을 고를 때 이 단어가 어떤 신호가 되는지, 헷갈리기 쉬운 점을 한두 문장으로 적습니다.
```

### 작성 팁

- 단어·발음·품사·한 줄 뜻(`meaning`)은 팝업 머리에 이미 크게 나오므로 `.md` 에 다시 쓰지 않습니다.
  `.md` 에는 그 뜻을 **이해하는 데 필요한 것**(뉘앙스, 여러 뜻, 문제 속 문장, 함께 쓰는 표현)만 적습니다.
- `##` 제목은 팝업에서 **작은 회색 구역 이름**으로 보입니다. 구역은 3~5개면 충분합니다.
- **굵게**, 목록, 인용(`>`), 인라인 코드, 표를 쓸 수 있습니다. 이미지·HTML 은 쓰지 않습니다.
- 팝업은 작은 카드입니다. **10~20줄**이 읽기 좋고, 길어지면 카드 안에서 스크롤됩니다.

## 3) 커밋 & 반영

기본 브랜치(`master`)에 커밋하면 다음 퀴즈부터 바로 반영됩니다. PR 로 올리면 `Content Check` 워크플로가 다음을 검사합니다. 로컬에서는 `pnpm test` 로 같은 검사를 실행할 수 있습니다.

- `index.json` 형식 (필수 필드, `id` 형식·중복)
- 같은 표현이 두 단어에 등록되었는지
- 폴더 안의 `.md` 가 모두 `index.json` 에 등록되었는지 (`README.md`, `_` 로 시작하는 파일 제외)
