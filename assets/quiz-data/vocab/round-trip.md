요청을 보내고 응답을 받아 오는 **한 번의 왕복**입니다. 왕복이 늘수록 지연과 비용이 쌓이므로 성능 문제에서는 **"왕복 횟수를 줄인다"** 가 자주 목표가 됩니다. 하이픈 없이 *round trip* 으로도 씁니다.

## 문제 속 쓰임
> Production metrics show your agent averages 4+ API **round-trips** per resolution.
> 운영 지표상 에이전트가 해결 한 건당 평균 4회 이상 API **왕복**을 한다.

## 함께 쓰는 표현
- **reduce round-trips** : 왕복 횟수를 줄이다
- **round-trip time (RTT)** : 요청을 보내고 응답이 돌아오기까지 걸리는 시간
- **an extra round trip** : 추가로 생기는 왕복 한 번

## 시험 포인트
왕복을 줄이는 문제에서는 필요한 도구 요청을 **한 턴에 묶어 보내고 결과를 한꺼번에 돌려주는** 것처럼, 구조를 크게 바꾸지 않고 불필요한 왕복을 없애는 선택지가 정답 쪽입니다. 필요할지 모르는 도구까지 미리 호출하는 방식은 비용·부작용만 키웁니다.
