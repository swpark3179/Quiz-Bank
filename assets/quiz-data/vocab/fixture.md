테스트를 돌리기 전에 **미리 준비해 두는 고정된 데이터·객체·환경**입니다. 테스트마다 같은 출발 상태(샘플 사용자, 가짜 DB 레코드 등)를 만들어 주어 결과가 매번 같게 나오게 합니다.

## 문제 속 쓰임
> ...and to know which **fixtures** already exist in the test helpers directory.
> 테스트 헬퍼 디렉터리에 이미 있는 **픽스처**를 알기를 원한다.

## 함께 쓰는 표현
- **test fixture** : 테스트 픽스처
- **set up / tear down a fixture** : 픽스처를 준비하다 / 정리하다

## 비슷한 말 · 반대말
- **mock** — 진짜 객체를 흉내 내는 대역 (*fixture* 는 미리 준비한 상태·데이터 쪽)

## 시험 포인트
테스트 품질 기준이나 *fixture* 목록처럼 **모든 CI 실행이 반복 없이 받아야 할 프로젝트 지침**은 저장소 루트에 커밋한 `CLAUDE.md` 에 둡니다. 워크플로 YAML의 `prompt`·PR 템플릿·셸 프로필은 반복되거나 세션에 로드되지 않아 오답입니다.
