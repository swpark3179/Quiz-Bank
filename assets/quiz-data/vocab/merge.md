둘 이상의 것을 **하나로 합치는** 것입니다. Git 에서는 다른 브랜치의 변경을 합치는 **병합**을 말합니다.

## 문제 속 쓰임
> **Merge** both tools into one `get_info(entity_type, id)` tool
> 두 도구를 하나의 `get_info(entity_type, id)` 도구로 **합친다**
> The system prompt and retrieved content **merged** into one effective context — ...
> 시스템 프롬프트와 검색된 콘텐츠가 하나의 컨텍스트로 **섞였다**

## 함께 쓰는 표현
- **merge A into B** : A를 B에 합치다
- **merge conflict** : (Git) 병합 충돌
- **merge a PR** : PR을 병합하다

## 비슷한 말
- **combine**, **consolidate** — 합치다, 통합하다

## 시험 포인트
모델이 비슷한 도구 둘을 헷갈릴 때 **도구를 하나로 합치는** 보기는 오답이 되기 쉽고, 각 도구를 *언제* 쓰고 *무엇을* 반환하는지 description 을 다시 쓰는 것이 정답입니다.
