**OpenID Connect** 의 줄임말로, OAuth 위에 **"이 사용자(워크로드)가 누구인가"를 증명하는 ID 토큰**을 더한 표준입니다. OAuth 가 '무엇을 해도 되는가(권한)'라면 OIDC 는 '누구인가(신원)'를 다룹니다.

## 문제 속 쓰임
> ...(b) registers a trusted **OIDC** identity provider...
> (b) 신뢰할 **OIDC** ID 제공자를 등록한다

## 함께 쓰는 표현
- **OIDC identity provider** : OIDC ID 제공자 (토큰을 발급·서명하는 쪽)
- **ID token** : 신원을 담은 서명된 토큰
- **token claims** : 토큰에 담긴 정보 항목

## 비슷한 말 · 반대말
- **OAuth** — 권한 위임 표준. OIDC 의 바탕입니다

## 시험 포인트
워크로드 ID 페더레이션의 세 자원은 **서비스 계정**(누구로 행동하나), **페더레이션 발급자**(신뢰할 OIDC 제공자 등록), **페더레이션 규칙**(토큰 클레임 → 서비스 계정·OAuth 범위·토큰 수명)입니다. 발급자와 규칙의 역할을 뒤바꾼 보기가 함정입니다.
